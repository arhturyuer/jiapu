## A4 完整谱书

- 固定 A4 竖版、双面左装订、长边翻页、实际大小／100% 打印。内侧 30mm、外侧 20mm、顶部 20mm、底部 22mm；奇数页内侧在左，偶数页内侧在右，正文、图块、表格、页眉和页脚统一镜像。封面背面留空，末尾按需补空页使总页数为偶数；封面与空白页无页眉页脚，章节不强制从奇数页开始。页码与实际 PDF 页序一致。
- 顺序为封面、编排说明与家谱简介、目录、全谱导览、家庭世系图、分代人物资料、姓名索引。全谱导览列各相对代次人数及世系／资料页范围；目录、图卡、亲属引用、导览与索引同时支持纸面页码和 PDF 跳转。人物编号 P001、图块编号 F001 仅对本次文件有效。
- 正文、目录、索引 14pt／21pt 行距，人物姓名 18pt，图卡姓名 16pt，章节标题 22pt，辅助文字最低 12pt。黑色文字、白底，关系线至少 0.75pt。长姓名换行、增高卡片，不缩小字号。短人物资料整块分页；长文本续页重复姓名、编号和“续”，中文标点按行首行尾规则换行。
- 世系图保留父母组合，按父母相对代次及编号稳定排序；小型家庭每页最多 3 个图块，按实际高度自动减少。每图最多 8 名子女，长姓名或内容过高时提前分段，重复父母并注明子女范围、承接与续图页码。多配偶分别展示；夫妻线仅依据已记录夫妻关系，不因共同子女推定婚姻。亲子线走卡片外侧及中央留白；无子女夫妻关系合并排版，单亲不补另一位父母。
- 图卡显示姓名、人物编号、资料页；有后续世系时显示“下接”图块与页码，全部相关图块列于人物资料。所有成员至少在图块出现，完整资料只收录一次；姓名索引沿用中文排序，四栏为姓名、编号、代次与出生年、资料与世系页。同名者保持独立条目，未知出生年注明未记。
- 完整保留姓名、性别、健在状态、生卒日期及历法／精度、出生地、简介、头像与亲属关系。未填写项目集中说明，不留无头像空框；已设置但不可用的头像注明不可用。代次沿用当前分组算法推导，不作宗族世次或房支考证，不连通或无法确认代次者列为“辈分待确认”。不补写历史事实或未记录亲属关系。
- 排版先测量内容和分页，确定人物／图块页码，再回填目录、导览、索引及链接并验证边界。改进版仅对重新生成文件生效，已有成品保持原内容；谱书本身无新增请求参数；大图新增可选快照参数，无集合、索引或数据迁移。当前轮部署与验收状态见交接记录。

## 服务端接口与任务

用户 API 沿用 `type`、`success/data` 协议：

| 动作 | 输入 | 输出 |
|---|---|---|
| `pdf.create` | `source=family/example`、`familyId/slug`、`format=poster/book`、大图 `display`、可选 `layoutSnapshot`、`requestId`；失败重试可传 `retryTaskId` | 公共任务状态 |
| `pdf.status` | `taskId`；无 taskId 时按 `familyId/slug`读取本人最近一次 PDF 任务 | `{task}`，无记录时为 null |
| `pdf.downloadUrl` | `taskId` | 临时 `url`、`fileName`、`expiresAt` |

- 新动作在 `youpuUserApi` 完成白名单、服务端鉴权、会员校验、幂等、每日次数和并发保护；每人最多一个进行中任务，不沿用备份的管理员限制或 7 天冷却。
- 复用 `export_tasks`，新增 `kind=family_pdf` 与必要的格式、显示设置、文件、进度和执行令牌字段。状态为 pending/processing/completed/failed/expired。`users` 增加 pdfDay/pdfCount/activePdfTaskId/latestPdfTaskId 可选字段；无需迁移旧记录，不新增集合或索引，schema v11 保持。
- 经现有受密钥保护的 SCF Event 派发 `task.pdf-export` 给 `youpuJobs`。不同任务类型严格隔离，旧个人导出、备份与复制接口保持原协议。新大图任务先由用户函数生成原生码并将图像保存在服务端私有任务记录，再派发；云任务不接受客户端码图或任意图片地址。码生成失败明确标记失败，重试原任务不重复计次；未准备好码的任务不能领取。创建和状态读取可恢复准备与派发 pending，重复执行只允许一次领取；旧任务无新字段仍兼容。
- 执行时分页读取完整资料，通过 contentRevision 前后比较、最多 3 次重读取得一致快照；示例只取已发布内容。大图携带布局快照时同时匹配入口来源版本，不将更新后的资料套用旧布局。执行前、上传前后重新检查权益及权限，旧执行令牌不能覆盖重试结果。
- 文件保存在私有 `exports/<用户>/<任务>-<执行令牌>.pdf`，复用现有到期删除及 processing 超时回收；新增 pending 超时维护。前台退避读取状态，离页停止轮询。
- 仅包含可访问、approved+active 的对应家谱头像；按服务端资源控制解码、旋转并压缩到 360px JPEG，文字和关系图保持矢量。单张头像下载或解码失败时大图占位、谱书注明不可用，并显示数量；照片处理运行依赖缺失时任务明确失败，不静默将全部照片降级为占位；不导出账号、订单、审核或运营资料。日志不记录人物资料和链接。

导出页标题为“家谱名称·导出”，两种格式显示为“家谱树大图”和“家谱书”，任务结果与无障碍标签使用相同名称；选择态通过卡片边框显示。大图说明为“完整家谱生成一页PDF，文字和关系线可放大打印，比例自适应。”及“沿用家谱图片的样式与显示设置。”；谱书说明为“打印装订成册，大字阅读、双面左装订，含导览、世系图、完整人物资料和姓名索引。”及“完整收录现有资料。”。真实家谱权益文案为“家庭会员全体家人可用。每人每天合计可生成20次。”，示例保留免费导出说明。页面简化说明不改变上述文件尺寸、码有效期、头像、辈分及下载期限规则。

开发版连接独立 staging；人工上传后的体验版与正式版连接 production。验收入口：真实家谱或官方示例 → 画布工具栏 PDF → 选择格式 → 生成 PDF → 预览 PDF/转发文件。导出页提供会员引导、错误重试、额度说明及缺失头像提示。首次转发尚未下载时先准备文件，再要求用户重新点击转发，以满足微信操作手势要求。

后台虚构资料验收先通过开发工具为当前 staging 项目开启 9420 自动化端口，并准备微信 miniprogram-automator SDK（本轮 0.12.1）。使用 `DEPLOYMENT_TARGET=staging STAGING_ENV_ID=<独立staging环境ID> WECHAT_AUTOMATOR_MODULE=<本地SDK绝对路径> node deployment/verify-pdf-staging.mjs --wechat`（完整矩阵）或追加 `--layout-only`（500 人／2000 条密集关系、真实导出页和拒绝路径），只允许与受控 staging 清单一致的目标。后台 CLI 没有微信云调用票据，不能替代客户端原生码生成。脚本部署受密钥保护的临时验收函数，创建独立虚构用户/家谱/示例；已登录开发版通过部署的用户 API 生成两份原生码 PDF，其余角色／额度用例复用同一虚构来源的码图。保存测试账户 PDF 计数与任务指针，存在进行中任务或并发变化时停止，完成后恢复；只为虚构家谱临时建立 viewer 身份，不读取生产资料，不修改函数调用权限。实际开发者工具布局模块产生版本快照，验证 500 人两种格式及三种角色、横排大图照片及原生小程序码实际嵌入、仅缺失照片计数为 1、公开示例大图和每日第 20/21 次边界，结果和样本留受控目录，完成后删除虚构资料、文件和临时函数。后台角色身份由验收函数注入，两份原生码由开发版真实用户 API 生成；这不等同于 iOS/Android 真机扫码、预览与打印验收；失败保留受控摘要，若任务仍在执行必须先确认状态再清理。

本地解析和渲染不能代替 iOS/Android 文档预览、文件发送及 A4 实际打印；500 人极端长宽比例大图的阅读器兼容性需要真机验证。AI 仅部署当前请求获授权的服务端环境，人工上传、提审和发布按[发布运行手册](./正式发布运行手册.md)执行。
