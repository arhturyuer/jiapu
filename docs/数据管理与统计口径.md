# 数据管理与统计口径

文档状态：现行规范。核验日期：2026-10-07。描述本地实现；云端部署和验收状态见[交接记录](./releases/数据管理-未发布-2026-10-03.md)。环境规则见 [AGENTS](../AGENTS.md)，入口见 [文档索引](./文档索引.md)。

## 入口与操作

运营后台「数据管理」对 `operator`、`super_admin` 开放。默认今天实时指标、当天转化窗口、真实支付，单日查询配近 30 天趋势。支持今天、昨天、近 7/30/90 天及自定义日期（最多 90 天），按北京时间（UTC+8）归日，包含起止日。今天显示“当日未结束”，数据截止到查询快照，缓存最多 30 秒。

用户增长、家谱增长、活跃、付费四个页签均提供指标、每日明细和趋势。人数、家谱数、订单及转化分子可点击下钻，汇总及每日指标对应查询快照支持稳定分页，继续进入受现有鉴权和审计保护的用户、家谱、订单详情。净收款为两组订单的差额，不提供一组名单。修改筛选后提示尚未查询并关闭下钻；加载失败可重试；离开页面忽略迟到结果。每日 CSV 仅导出已查询筛选，包含分子、分母、日期、支付环境、观察窗口、统计截止、口径和完整性标记，金额以元表示。

## 指标口径

| 指标 | 口径 |
|---|---|
| 每日新用户 | `users.createdAt` 归日，首次进入完成建档的去重用户；包含之后冻结、注销的保留记录 |
| 进入真实家谱转化率 | 当天新用户在窗口内成功打开自己创建或已加入的真实家谱图或家庭页人数 / 当天新用户数 |
| 示例体验率 | 当天新用户在窗口内成功浏览已发布官方示例人数 / 当天新用户数；与真实家谱分别统计 |
| 创建家谱转化率 | 当天新用户在窗口内至少创建一份家谱人数 / 当天新用户数 |
| 加入家谱转化率 | 当天新用户在窗口内至少加入一份其他人创建的家谱人数 / 当天新用户数；仅查看角色也计入 |
| 每日新建家谱 | 当天成功创建的家谱数，同一用户创建多份分别计数；包含之后归档、冻结及启用后清理的保留事实 |
| 曾有家人加入比例 | 当天新建家谱在窗口内曾有非创建者用户加入的家谱数 / 当天新建家谱数 |
| 当前协作比例 | 同一批新建家谱在查询时点仍有效且有非创建者有效成员的家谱数 / 当天新建家谱数；不受加入观察窗口限制 |
| 每日活跃用户 | 当天实际进入或使用小程序的去重用户，包含示例浏览；后台任务、运营访问、支付回调不计入 |
| 每日活跃家谱 | 当天被有效成员访问、维护、创建或加入的真实家谱去重数；示例和邀请预览不算真实家谱活动 |

当天/7 天/30 天从建档或建谱当天北京时间零点起算 1/7/30 个自然日，并且事件时间不得早于建档或建谱时间；观察至查询时点，可以观察选定队列日期之后发生的转化。窗口未满标为暂定值。创建、加入、进入可能重叠，比例不能相加；期间比例用总分子 / 总分母，不平均每日百分比。没有分母显示“—”，完整采集且无行为显示 0。今日新建家谱可能由老用户创建，不能直接用今日新建家谱数推定今日新用户的创建转化；行为必须归属于同一批新用户，界面提示并可下钻核对建档/首次行为时间。家谱中的人物数量不代表加入用户数。

## 采集、历史与性能

用户建档使用事务，防止并发登录覆盖首次信息。创建和加入的业务事务保存可选 `users.firstCreatedFamilyAt`、`users.firstJoinedFamilyAt`、`families.firstRelativeJoinedAt`。重新加入保留 `family_memberships.firstJoinedAt`。首次访问分别记录 `users.firstEnteredFamilyAt`、`users.firstExampleViewedAt`。

新客户端前台进入、成功获取真实家谱/家庭页或示例（含缓存命中）时上报，已有图谱/示例页面重新显示也上报；每用户每天按事件及目标去重，失败允许后续重试。服务端验证可用用户、有效家谱成员或已发布示例；家谱采集沿用现有 `requireMembership(familyId, roles, scope, openid)` 参数契约，使用北京时间日、kind、entityId 的确定文档 ID 和事务去重。自动采集异常只记录脱敏错误，不改变已完成业务结果。旧客户端用成功业务调用补充采集，纯本地缓存访问需新客户端发布后才能覆盖。

集合用途：

| 集合 | 用途与保留 |
|---|---|
| `analytics_activity_daily` | 每日用户/家谱去重活动事实，仅保存日期、kind、业务标识、采集时间，无姓名、openid、访问内容 |
| `analytics_daily` | 按日、窗口、支付环境保存无个人标识的聚合，可根据事实重建 |
| `analytics_reports` | 日期范围汇总缓存，有效 30 秒，避免重复刷新扫描业务集合 |
| `analytics_snapshots` | 汇总对应的明细快照元信息及计数，24 小时有效 |
| `analytics_snapshot_items` | 按指标分块保存脱敏事实，分页与汇总一致；每块 100 条，24 小时有效 |
| `analytics_history` | 家谱清理前保留创建者、创建时间和首次加入事实，不保留姓名、内容、openid；仅供统计与已清理标记 |

初始化幂等写入 `system_config/analytics.trackingStartedAt`，重跑不重置。首次采集当天与之前的访问不完整，DAU、活跃家谱、进入和示例转化显示“—”；从之后首个完整北京时间自然日起展示。跨缺失日期的期间访问指标也显示“—”，完整日期仍显示实际值。

历史创建、加入用现存家谱、成员、可确认的加入审计及保留事实补充；旧版本覆盖首次加入时间可在审计仍存在时恢复。启用之前已经清理或完全丢失的记录无法恢复，访问不补造。之后注销保留去重支付统计标识，清理家谱先保留无内容事实和日聚合；明细标记已清理。过期快照和范围缓存由已有每日保留任务清理。

查询只按日期和关联 ID 读取业务事实，未缓存时重建聚合与明细快照。单个读取集合最多 20,000 条，明细每页最多 100 条；超限返回明确错误并要求缩小日期范围，不能静默截断。大量首次查询仍受云函数运行时间限制，应按较短范围查询并验收实际耗时。当前协作与有效会员是查询时点状态，按快照固定，不用于重建过去时点状态。

## 付费数据

范围为家庭会员订单，默认 `paymentMode=live`，支持 `sandbox`、`mock`、全部；支付环境缺失的旧订单仅出现在“全部”，不推定为真实支付。

- 创建订单按创建日；成功支付订单和金额（GMV）按 `paidAt`；退款笔数和金额按 `refundedAt`，退款保留原支付记录。
- 当前系统整单退款，使用完整订单金额。净收款＝期间支付金额－期间退款金额，可为负，未扣平台费用。
- 付费用户、付费家谱按成功支付订单去重；不能相加每日人数作为期间人数。用户注销后的去重标识保持一致。
- 订单支付转化按创建日队列，观察至查询时点，已成功支付（包括退款）的订单数 / 创建订单数，独立于新用户转化窗口。
- 客单价＝支付金额 / 成功支付订单数；ARPPU＝支付金额 / 付费用户数；商品结构按成功支付归组。
- 当前有效会员家谱按永久或未过期权益、有效家谱 ID 去重，同一家谱两条件同时满足只计一次。此指标显示所有支付环境的当前权益，与收入筛选不同。

## 接口与部署

| 接口 | 输入与输出 |
|---|---|
| `analytics.track`（用户 `type`） | `{ kind: 'foreground'|'family'|'example', familyId?, slug?, requestId? }`，身份从服务端会话取得；返回 `{ recorded: true }`；登记 mutation、限流（每用户每小时 300 次），按日幂等 |
| `analytics.summary`（运营 `action`） | `{ startDay?, endDay?, window?: 'day'|'7d'|'30d', paymentMode?: 'live'|'sandbox'|'mock'|'all' }`，默认今天、当天、真实；返回 `filters/timezone/asOf/generatedAt/trackingStartedAt/activityComplete/rows/totals/sku/snapshotId` |
| `analytics.details`（运营 `action`） | `{ snapshotId, metric, startDay, endDay, window, paymentMode, pageSize?, cursor?, day? }`，必须与汇总筛选一致；返回 `items/total/hasMore/nextCursor/asOf`，记录运营查看审计 |
| `commerce.detail`（运营 `action`） | `{ orderId }`，返回现有脱敏订单字段并记录访问审计 |

沿用 `success/data`、`success/code/message` 协议。非法日期、快照、指标、游标分别返回稳定错误；未登录、非白名单或不匹配角色在读业务数据前拒绝。`asOf` 窗口作为服务端内部兼容值保留，界面仅显示已确认的三种窗口。

部署包含 `youpuJobs`、`youpuUserApi`、`youpuOpsApi`、上述集合初始化、索引 v11、客户端 deny-all 规则及后台；schema v11。新增字段可选，旧 API 协议不变。先部署 jobs 并 bootstrap，再确认集合规则和索引，然后部署用户/运营函数及后台，逐项回读。初始化不清空或复制数据。部署遵守 [staging 手册](../deployment/staging-runbook.md)。

本地统一运行 `bash scripts/check.sh`，后台构建显式指定独立 staging 的 `VITE_CLOUDBASE_ENV` 并加 `--build-admin`。专项测试见 [analytics.test.js](../tests/analytics.test.js)。云端验收需 staging 运营登录、两名虚构用户建谱/加入、重复和缓存访问、跨日、沙箱支付/退款及 CSV；非白名单与跨家谱访问必须拒绝。小程序上传、体验版设置、提审和发布由人工完成。


## 复制创建口径

复制任务成功发布时才写入新家谱 `createdAt`、复制者 `firstCreatedFamilyAt`（已有值不覆盖）和创建审计；计为一次新建家谱与该用户创建转化。接受任务、处理中及失败均不计新建；重复派发不重复发布。副本只带复制者一名管理员，不继承原谱曾加入或协作事实；后续真实邀请加入按既有口径统计。后台复制任务不生成用户前台日活事实，用户打开新谱后按原访问口径采集。
