# 版本交接模板

复制为对应版本记录后登记到[文档索引](../文档索引.md)。新记录属于历史记录，顶部标注“文档状态：历史记录；记录时点：实际日期；不作为当前操作指引”，链接[正式发布运行手册](../正式发布运行手册.md)。未执行项目写“未执行”，不得默认勾选通过。

- 功能范围、服务端/客户端变更、关联文档及核验日期：
- 未更新文档的理由（如适用）：

## 环境与授权

- 本次目标 staging/production、实际环境标识、部署时间与执行者：
- production 当前请求的明确授权依据（历史授权不能复用）：
- staging 实际 ID 留本机受控记录；仓库只保留记录编号，不提交本地配置或密钥：
- 人工平台配置项及完成证据：

## 验证和兼容

- 本地检查/构建命令、时间、结果、失败或跳过项：
- staging 验收入口、虚构测试数据标识及结果：
- 当前正式客户端与待审版本兼容性证据：
- 接口、索引、安全规则、schema 变化与迁移需求（无则写无）：
- 实际部署组件、回读结果、服务端验收入口：
- 回滚代码版本、适用条件、数据兼容性和待确认订单处置：
- 证据放持久受控位置；仓库可留脱敏摘要和引用，不仅依赖临时目录日志：

人工上传工具：`bash deployment/upload-miniprogram.sh {staging|production} <版本号>`；AI 不执行。参数只校验预期路由，不生成隔离的体验包。开发版 `develop` → staging；体验版 `trial`、正式版 `release` → production。体验/正式验收需当前生产授权及生产测试账号。
