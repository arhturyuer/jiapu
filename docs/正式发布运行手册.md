# 有谱正式发布运行手册

## 一、硬性发布门槛

每个版本发布到 production 前，必须同时满足以下条件：

1. 本版本功能已部署到独立 staging 环境。
2. staging 已完成与本版本改动相匹配的测试验证，且结果通过；至少包括自动化测试、构建和必要的功能验收。
3. 发布负责人在当前发布请求或发布记录中，明确确认“发布到 production”。未出现明确确认时，一律只允许部署 staging。
4. 生产部署命令必须通过仓库现有的 production 目标与确认护栏；不得修改、删除或绕过护栏。

生产数据备份、恢复演练、平台资质、告警和完整回归属于长期运维与风险控制要求，应持续维护；除非本次变更涉及数据迁移、清理、恢复或高风险数据操作，否则不作为常规版本发布的额外阻塞条件。

## 二、预发布部署

1. 记录 production 与 staging 的环境 ID、套餐、地域和负责人；当前 production 环境为 `cloud1-d5gs5yj4l283d9c6d`，staging ID 仅保存在本机忽略配置中。
2. 小程序按官方 `miniProgram.envVersion` 运行时路由：开发版 `develop`、体验版 `trial` 连接 staging，正式版 `release` 连接 production，未知值降级 staging。上传脚本只验证该映射，不生成不同环境的代码包。不得修改受版本控制的 `miniprogram/config/env.js`，也不得删除 `env.local.js` 来切换环境。
3. 应用集合、索引、数据库/函数安全规则；使用 `ALLOW_PERSONAL_PRIVATE_STORAGE=1` 显式确认个人套餐的 `PRIVATE` 存储生产基线，并回读验证权限未变为公开读写。
4. 配置三个云函数的 Nodejs20.19、超时、内存、环境变量、OpenAPI 权限和四个定时触发器；触发器名称和 cron 必须与 `deployment/cloudbaserc.example.json` 完全一致。
5. 执行 bootstrap，创建 Auth v2 初始用户与运营白名单。
6. 构建并部署运营后台静态站点。
7. 配置内容审核回调、告警和定时任务。
8. 先在独立 staging 环境部署本版本并完成测试验证；生产预检仅在收到明确 production 确认后执行。
9. 发布负责人明确确认 production 发布后，上传体验版并按本版本风险完成真机复验：体验版应连接 staging；同一包在正式发布后应依据 `release` 自动连接 production。

## 三、生产备份与恢复演练（长期运维要求）

在变更前记录生产环境 `cloud1-d5gs5yj4l283d9c6d` 的所有集合、记录数、索引、存储对象键/大小/ETag、云函数版本和环境变量（密钥只记录密钥版本，不导出明文）。

数据库备份必须同时满足：

- CloudBase 控制台存在本次变更前可选择的恢复点；
- 另有一次完整集合导出，保存在与生产环境故障域隔离的位置；
- 每日备份目标保留 30 天。个人套餐平台保留期不足时，通过定时导出到独立存储补齐，不能用 `backup_manifests` 代替真实备份。

`backup_manifests` 只记录每日集合计数，用于发现备份缺口，不包含业务数据。

恢复演练要在新集合或独立环境完成，禁止覆盖生产。至少核对：全部集合存在、总记录数一致、用户/家谱/人物/关系抽样可关联、媒体对象数量一致、唯一索引可重建、运营账号仍需重新校验白名单。

## 四、首次初始化、数据迁移或高风险变更

以下步骤仅适用于首次初始化、数据迁移、批量清理、恢复或其他高风险生产变更；常规功能版本按“硬性发布门槛”执行即可。

1. 冻结生产写入窗口，确认无正在处理的注销、归档删除或内容审核任务。
2. 再次生成数据库恢复点、数据导出和存储清单，双人确认可恢复。
3. 仅在上一步完成后清空旧业务集合；不要删除云环境本身。
4. 部署三个新云函数，bootstrap 集合，创建索引并应用安全规则。
5. 保留旧 `familyFunctions` 但仅作为上一版小程序回滚入口。
6. 用生产测试账号执行最短冒烟：新建家谱、邀请三角色、成员申请、管理员审核、全谱/视角、举报、媒体审核、归档恢复、注销取消。
7. 运行生产预检：`PREFLIGHT_MODE=production ALLOW_PRODUCTION=1 TARGET_ENV_ID=cloud1-d5gs5yj4l283d9c6d ./deployment/preflight.sh`。生产写入脚本还必须显式设置 `DEPLOYMENT_TARGET=production ALLOW_PRODUCTION_CHANGE=1`。
8. 在 `miniprogram/config/release-notes.js` 顶部新增本次版本与更新摘要后，使用 `bash deployment/upload-miniprogram.sh production <版本号>` 验证正式版运行时映射并上传待审核包，再提交微信审核；审核通过后由负责人手动发布。发布后用生产测试账号完成最短冒烟，确认 `release` 已连接 production。
9. 观察 30 分钟核心指标，再逐步通知家庭群使用。

## 五、监控与告警

三类云函数日志字段固定为 `requestId / actorId / action / durationMs / success / resultCode`。`actorId` 是不可逆内部标识，不记录姓名、简介、邀请令牌、图片地址或原始 openid。

配置以下告警：

| 指标 | 阈值 | 处置 |
|---|---|---|
| 5 分钟错误率 | > 2% | 暂停发布/回滚客户端，按 requestId 排查 |
| API P95 | > 2 秒 | 检查慢查询、索引、内容审核与资源配额 |
| 审核队列最老任务 | > 30 分钟 | 检查回调，切人工复核 |
| 数据库/函数/存储用量 | > 80% | 扩容并检查异常增长 |
| 注销 `failed` | 任意新增 | 运营工单重试并记录原因 |
| 家谱 `deleting` | 超过 30 分钟 | `youpuJobs` 自动续跑，仍失败则人工介入 |

## 六、回滚

- 小程序异常：回滚上一审核版本；不要回滚已经成功提交的数据库事务。回滚后确认正式版 `release` 仍路由到 production。
- 新用户 API 异常：将上一版小程序继续指向旧 `familyFunctions`，保留新集合现场；修复后从预发布重新验收。
- 管理端异常：回滚静态托管上一版本，不允许运营人员直接改数据库。
- 定时任务异常：先停触发器，再保留失败状态与 requestId，修复后幂等重跑。
- 数据损坏：停止写入，复制生产现场，优先在新集合恢复并校验后切换；禁止直接覆盖唯一可用副本。

生产稳定观察期不少于 7 天。确认无旧版调用后再应用 `function-rules-after-stabilization.json` 并停用旧函数。
