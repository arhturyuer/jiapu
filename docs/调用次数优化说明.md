# 调用次数优化说明

本文为现行规范，描述截至 2026-10-13 的实现与验收边界。环境授权仍以 [AGENTS](../AGENTS.md) 为准；三阶段 SDK 对照见[staging 交接](./releases/云数据库调用优化-staging交接-2026-10-13.md)，用户确认验收后的生产交付见[生产交接](./releases/云数据库调用优化-生产交接-2026-10-13.md)。生产服务端与后台部署完成，小程序 v1.6.14 待人工发布。

## 诊断依据

用户授权 production 只读监控后的 2026-10-05～11 完整七天记录：数据库读 222,874 次、写 67,609 次，云函数执行 29,000 次；仅这三类指标中数据库约占 90.9%。用户接口日志中角标 5,581 次、会员状态 3,906 次、登录 2,628 次，合计约占 44%。用户、家谱、成员关系集合约占数据库读取 68%，其中既有必要鉴权也有统计补采集的重复读取。报表明细块七天写 7,142 次，含创建和维护删除。

截图的总调用次数包含数据库、函数、存储等资源调用，不等于用户点击或云函数执行。总配额展示、资源监控、日志有不同窗口和上报延迟，不直接拼成账单或计算人均滥用。每天一个维护触发器仍可能产生大量逐条数据库操作。一个匿名身份的调用集中度不是异常访问定论。[官方指标说明](https://cloud.tencent.com/document/product/876/118752)、[监控接口](https://cloud.tencent.com/document/product/876/129258)。这些是当时的诊断证据，不是新的生产授权。

## 缓存与鉴权规则

| 对象 | 缓存与刷新 | 失效边界 |
|---|---|---|
| 用户登录 | 公开资料跨启动最多 24 小时；冷启动先确认身份；合并并发 | 强制登录、账号状态错误、账户生命周期操作和本机重置 |
| 待审核角标 | 环境、用户、家谱隔离，5 分钟；图谱和家庭看板回填原始来源时间 | 审核提交／完成、相关家谱写入、角色变化、切谱及下拉刷新 |
| 广告展示权益 | 环境、用户、家谱隔离，最多 5 分钟，图谱／看板共享结果并合并并发 | 到期时间、购买／兑换／退款确认、角色／家谱状态变化、切谱、下拉刷新及权限错误 |
| 访问去重 | 本机按环境角色及实际云环境 ID、用户、北京时间日、事件及目标保存成功标记，最多 200 项 | 跨日、换账号／环境、本机清理；失败不确认、允许重试 |
| 报表 | 服务端 5 分钟持久缓存与同实例并发合并；页面共享相同筛选的单日和趋势结果 | 到期、筛选变化、支付模式变化；失败不留正在执行状态 |

客户端业务缓存仍为 1 小时，通用媒体临时链接仍为 10 分钟。后续“我的”页个人头像以资源 ID 隔离并持久保存已审核的本地图片，未更换头像时跨启动长期复用；反馈群二维码在我的页和独立页共享本地图片与 12 小时缓存，命中不调用 `feedbackGroup.get`。头像更新、文件丢失、清除本机缓存以及二维码到期或手动重试后重新获取；下载失败不写入持久缓存。其他设备的角标／广告权益变化在缓存过期后的下一次页面加载确认；用户下拉刷新立即回源。缓存不自动发起周期云请求。会员到期前截短展示权益缓存，未知权益和查询失败仍隐藏广告。购买、备份和导出等业务始终通过服务端实时授权。

服务端 `request-context.js` 使用 AsyncLocalStorage 隔离每次调用的已验证对象，用于普通只读请求与统计补采集复用；每个新请求仍读库鉴权，事务尝试另建上下文、每次重试重新读取，mutation 完成后清空以获取提交后的状态。保留旧客户端成功业务调用补采集和服务端每日事务去重。热实例内存不是权限或可靠去重的来源。[官方实例复用说明](https://docs.cloudbase.net/cloud-function/instance)。

成功标记仅在服务端返回成功后保存。跨日、重置、环境或用户变化期间的迟到结果不落盘；存储失败不影响业务，服务端继续负责去重。只保存每日事件标记，不保存姓名、内容或媒体地址。

## 报表与保留期维护

报表筛选、汇总、明细、CSV 与既有 snapshotId 协议不变。5 分钟缓存不改变指标定义，界面仍展示统计截止时间；客户端有效期取服务端 asOf 加 5 分钟和本地收到时间加 5 分钟的较早者，防止叠加缓存年龄。跨实例可能同时构建相同筛选；已有持久缓存减少后续重建，不宣称全局只执行一次。

批删仅用于 `idempotency_records`、`rate_limits`、`analytics_snapshots`、`analytics_snapshot_items`、`analytics_reports` 的原过期清理。先按原条件选最多 100 个明确 ID，再以 ID 集合 AND 原条件删除；选择和删除之间延期的记录保留。选择数和删除数均受原总量上限约束，零删除退出，避免循环。不得依赖 limit 限制删除范围，不改变保留期限、业务删除或媒体清理。[官方批量删除说明](https://docs.cloudbase.net/api-reference/server/node-sdk/database/delete)。

## 验证与部署

本地执行 `bash scripts/check.sh`；并发默认 4，繁忙桌面可设置 `CHECK_TEST_CONCURRENCY=1`～`4`，500 人 1 秒门槛仍不变；后台构建显式提供独立 staging 的 VITE_CLOUDBASE_ENV 并加 `--build-admin`。回归覆盖缓存计数、到期、强制刷新、切谱／账号／环境、迟到结果、统计重试与跨日、请求并发隔离、事务独立、报表并发与快照年龄、批删边界和探针生产拒绝。

staging 探针通过受控基线源码与部署后回读源码，在同一虚构用户和家谱下比较登录、角标、会员状态、图谱补采集、31 秒后重复报表、101 条过期记录清理的 SDK 读写操作数；同时检查冻结账户拒绝、快照明细一致及未来到期记录保留。探针使用临时随机密钥、固定运行标识和 staging 环境校验，结束清理数据、移除函数。记录保存到被 Git 忽略的受控备份目录；仓库交接仅保留脱敏结果与记录编号。

SDK 操作数是指定场景的对照，不是平台账单降幅；客户端测试不是实际微信设备验收。每轮 staging 开发者工具及 iOS／Android 均需验证切页、审核、会员变更、下拉刷新和统计跨启动；未完成项保持待验收，不能用本地通过代替。2026-10-13 本轮全部验收完成由用户确认；不补写未提供的逐设备材料。后续生产操作仍需当前请求明确授权，小程序上传、体验版、提审和发布由人工完成。

## 2026-10-13 持续优化阶段 1

本地新增分享漏斗 50 ID 批读、运营家谱列表两集合分组计数、用户与运营幂等事务一次完成写入、家谱内容版本与业务字段合并更新、媒体资源预生成 ID 一次创建，以及同请求／同事务尝试内的已验证对象复用。每次新请求仍重新鉴权；角色判断、事务重试与提交后统计失效保持。审计、幂等期限及旧记录读取不变。

计量覆盖真实路由、限流、统计与事务，并将事务重试和函数调用单列。冻结基线为本机受控 `call-reduction-20261013/baseline`；对照脚本 `deployment/verify-database-calls-staging.mjs` 仅允许独立 staging、密钥及运行标识匹配，回读已部署源码后运行，结束清理虚构数据和临时函数。当前阶段云端结果在交接记录中单独登记，不能将本地模拟算作云端验收。

## 2026-10-13 持续优化阶段 2

新增 `auth.identity`，只返回平台身份对应的用户 ID，不读取用户业务记录，不进入统计补采集，不证明账户或家谱权限；staging 身份映射仍真实读取。正常账户的公开资料按 AppID、实际环境、用户及原始时间保存最多 24 小时，冷启动先核对身份，未知接口回退完整登录，确认失败不展示旧资料。首次当天前台采集未确认时直接完整登录并消费成功回执。非正常账户不进入长期缓存；隐私页和手动刷新强制完整登录；账户操作、拒绝及重置清除缓存；本机资料更新不延长原到期时间。

新增可选 `graph.get.includeStatus`，附带 `pendingCount/membershipStatus/statusAsOf`；看板附带权益和来源时间。新客户端等待正在执行的组合读取，共享两种状态最多 5 分钟，回填不重置旧数据年龄，权益到期截短。旧接口仍兼容，缺字段时独立补查。资料更新、内容修改、审批／拒绝按影响范围失效，服务端可选 `familyCounters` 为事务确认的计数／关系版本，不能以客户端猜测代替。偏好保存合并窗口为 1.5 秒，失败重试沿用幂等键，最终无变化不发送。

成功响应可选 `meta.actorId/activityReceipts`。回执仅在统计成功后记录，客户端验证原会话、环境、用户和北京时间日期后保存；跨日、换账号、重置期间的迟到结果不确认。身份接口不采集事件；旧客户端补采集保持。云端和真机状态以本轮交接为准。

## 2026-10-13 第三阶段：聚合与受控维护

看板用一次 `persons` 聚合读取实际人数和五项字段总分，保留 JavaScript 字段真假值、`unknown` 性别排除及四舍五入口径；超过 500 人仍明确拒绝，协作者和待审列表的角色、500 条上限保持。聚合语法以 [CloudBase group](https://docs.cloudbase.net/api-reference/server/node-sdk/database/aggregate/stages/group) 和 [ifNull](https://docs.cloudbase.net/api-reference/server/node-sdk/database/aggregate/operators/ifNull) 为依据，实际部署 SDK 对照另列。

报表每次构建建立原始文档映射。只对同集合、无附加条件的 `_id` 查询补查尚未读到的 ID；加工对象及历史集合不充当当前原始记录，不跨构建共享。保留 5 分钟报告、冻结快照及 24 小时明细协议。PDF 状态读取复用已验证账户的任务指针，任务所有者和家谱权限仍校验。

任务函数新增独立 `maintenance-batch.js`，只允许已领取的注销匿名化与 `deleting` 家谱清理中的原集合／所有者条件，每批最多 100 明确 ID，并附加原条件。每批回读任务状态；选择数和处理数均受原上限约束，按 `_id` 稳定推进，零处理退出，失败沿用原恢复入口。文件与统计事实先保留／清理，记录删除顺序保持；过期清理允许列表、管理员计数、权益重算及不同值逐条写入保持。

完整三阶段交付、调用对照与未完成项见[本轮交接](./releases/云数据库调用优化-staging交接-2026-10-13.md)。SDK 调用数是实际查询／聚合／写入操作数，不能直接视为计费读写单元或生产整体降幅。
