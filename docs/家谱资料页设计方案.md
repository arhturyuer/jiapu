# 家谱资料页设计方案

> 文档状态：现行规范；核验日期：2026-10-27。本轮实现文字资料页、编辑及管理优化；本地检查与 staging 实际结果见版本交接，不能以设计预览代替功能验收。现行能力见[当前能力与边界](./当前能力与边界.md)，视觉依据见[设计规范](./有谱设计风格规范.md)，开发交付遵守[开发规范](./开发规范.md)。

## 1. 目标与现状判断

用户已选择：结构化文字资料、家庭页顶部展示，以及将“共同维护”改为“已加入的家人”。本轮按用户明确要求实施，并仅面向独立 staging 部署验收。

优化前资料只有名称和200字简介，混在家庭与权限管理表单里，且仅管理员能看到。简单增加输入框会继续让资料像设置项，长篇内容也不适合塞进家庭页首屏。新结构采用“家庭页摘要 → 同页资料阅读／编辑”，管理员在原页切换整页编辑，权限管理仍独立。

## 2. 页面与内容层级

### 家庭页入口

- 顶部资料卡仅展示名称、简介、概况和重点摘要，标题旁右箭头表示可进入完整资料，整卡可点击；邀请和角色放在卡片下方，人物完整度位于统计区域，会员和编写记录移入管理列表。
- 展示家谱名、最多两行简介；未填简介省略。姓氏、祖籍、堂号以标签与内容对齐的信息行展示已填项，长内容自然换行，不使用散列绿色标签。
- 允许管理员选择一项重点内容：家训、字辈或家族历史；默认“仅展示家族概况”，不自动替家族挑选。重点摘要最多两行，点击仍进入完整资料页，不用轮播或自动滚动。
- 原有会员权益、人物资料完整度、邀请及编写记录保留原有语义；完整度不纳入新资料字段，不鼓励为了分数填满堂号等选填内容。预览聚焦新资料区域，其他运营模块不作为删除依据。
- 家庭页统计“共同维护”改为“已加入的家人”，原人物数和加入人数口径不变。

### 家谱资料阅读页

顺序固定为：标题与访问说明 → 简介 → 家族概况 → 字辈 → 家训 → 家族历史 → 资料编写记录。正文在同一阅读底面分章，细线和留白区分章节；不显示目录或章节跳转入口。

| 区域 | 展示规则 |
|---|---|
| 标题区 | 家谱名称、完整简介，简介始终显示标题与正文位置；“已加入家人可见”为辅助信息，仅管理员显示“编辑资料”；不重复显示“家谱资料”眉题 |
| 家族概况 | 姓氏、祖籍、堂号以标签和值逐行对齐；空字段保留标签、显示“未填写”；不按姓氏推断堂号或族源 |
| 字辈 | 保留原始顺序和换行，使用统一正文；不自动逐字拆分或生成当前辈分 |
| 家族历史 | 整篇连续展示，不截断、不折叠；保留段落和换行，允许注明口述、旧谱等来源与待核实信息 |
| 家训 | 保留换行，使用与字辈、历史一致的正文样式 |
| 编写记录 | 进入现有家谱范围的资料编写记录页；不把家谱全部变更误标为“本页资料的最后编写者” |

阅读状态始终展示全部8个文字字段：名称作为页首主标题，简介单独标注，概况保留姓氏、祖籍、堂号三行，字辈、家训、历史各自保留章节。已填写值显示完整实际内容；未填写的值显示“未填写”，不显示整页空态引导，也不生成推断内容。全部角色使用相同资料结构，编辑入口仍仅管理员可见。

### 同页编辑状态

- 阅读和编辑合并为同一页面的两个状态，默认阅读，仅管理员可切换编辑。编辑时名称、简介、姓氏、祖籍、堂号、字辈、家训、家族历史连续展示，不切组、不折叠；“取消／保存资料”固定在页面底部统一提交，包含安全区，正文根据底栏实测高度加24px留白；字号、窗口和编辑状态变化时重测。
- 只要求名称，其他均为选填。祖籍、堂号为自由文字，不强迫选择现代行政区，不推断资料是否符合姓氏。
- 多行输入保留换行；计数与长度限制使用前后端一致口径。文本框有可见标签，提示不能代替标签。
- 提示示例：字辈“按原顺序记录，保留换行；没有字辈可以留空”；历史“可以记录家族起源、迁徙和重要往事；尚未核实的内容可注明来源”。
- 重点展示设置位于编辑表单后方，说明其影响家庭页；不允许选择空内容。清空当前重点字段时提示改选或设为“仅展示家族概况”，保留草稿。
- 保存时校验全部字段，错误显示在对应字段并滚动定位；重复保存禁用。成功使用服务端返回资料更新缓存并在原页回到阅读状态；失败保留输入并提供重试。未更改时保存禁用；修改后返回或取消先确认放弃，取消留在本页阅读状态。请求未完成前不允许重复提交或丢弃页面。
- 草稿仅保留在当前页面编辑状态，不另加持久本地草稿。切换账户／家谱、失去权限时禁止写入旧目标，提示重新加载。编辑时下拉刷新不覆盖草稿，隐藏再返回重新确认权限；隐藏期间保存成功，回到页面后展示结果，账户变化或页面卸载后不把迟到结果写入页面。

## 3. 家人及邀请管理

- 管理页标题为“家人权限与家谱管理”；资料表单移到独立页，管理页保留“家谱资料”入口。家庭页管理列表同步更新入口与说明。
- 列表标题“已加入的家人”，说明“这里是已加入这份家谱的使用者，与谱中记录的人物不同。”包括管理员、普通成员及只读访客；不将人数描述为实际编写人数。
- 角色名称使用“家谱管理员／家庭成员／仅查看”；管理员可管理资料、审核申请和家人权限，家庭成员可提交新增或修改申请、管理员审核后生效，仅查看角色不能修改资料。已核对现有新增人物与修改人物服务端分支，本轮不更改权限规则。
- 管理员的每人操作集中为“管理权限”，复用原有角色调整、增设管理员和转让身份接口及确认，不引入新的授权模型。最后管理员等约束继续由服务端校验。
- 邀请管理仅管理员可见，默认显示标题及“展开查看”，未读取前不显示虚假的0条或总数。展开后懒加载，加载／空态／错误与重试／列表及分页各自显示；折叠保留本页已加载数据，撤销后更新数据且保留展开状态。
- 撤销前说明“撤销后，尚未加入的家人无法再通过此邀请加入；已加入的家人不受影响”。切谱或重新进入页面恢复默认折叠；没有邀请时仍保留管理入口。
- 数据与退出仍为单独分区，不放进资料阅读页。邀请卡角色文案、指南及其他页面的协作概念不做机械全文替换。

## 4. 接口与实现边界

统一使用 `/pages/family-profile/index?familyId=…`，可选 `edit=1` 请求进入编辑状态但仍校验权限；原 `/pages/family-profile-edit/index?familyId=…` 仅兼容重定向至统一页，沿用原生小程序、现有导航与阅读偏好。服务端保留 `family.update`，在家谱中增加以下可选字段：

| 字段 | 含义 | 字数上限 |
|---|---|---|
| `name`（已有） | 家谱名称 | 40，必填 |
| `description`（已有） | 简介 | 200 |
| `surname` | 姓氏 | 40 |
| `ancestralHome` | 祖籍 | 100 |
| `hallName` | 堂号 | 100 |
| `generationPoem` | 字辈 | 1000 |
| `history` | 家族历史 | 3000 |
| `familyMotto` | 家训 | 2000 |
| `featuredSection` | 重点展示 | `none`／`generationPoem`／`history`／`familyMotto` |

新增只读动作 `family.profile`：输入必填 `familyId`，有效家谱成员可读，缺失或非法 `familyId` 返回 `INVALID_FAMILY_PROFILE`，返回 `{family, profile}`，其中 `profile` 含完整新增文字字段及重点设置；不新增写入幂等要求，归档、退出、未登录和无权访问沿用既有错误码。列表、图谱与家庭看板的 `family` 仅增加姓氏、祖籍、堂号、`featuredSection`、`featuredLabel`、最多100个字符的 `featuredExcerpt`，不返回完整长文。旧记录缺省为空、重点为 `none`；旧客户端更新未提供的新字段时保留原值，显式空字符串清空。新增文字字段对非法类型、超长和空重点返回 `INVALID_FAMILY_PROFILE`，名称及简介沿用旧协议；对字段类型、长度和重点内容进行服务端校验，编辑权限维持管理员，读取维持有效家谱成员权限。现有名称与简介协议不变，不能因新客户端缺少信息覆盖既有资料。

沿用文字安全检查，按不超过500字分块，每批最多四块，覆盖所有长文本并分批检查，全部通过后再事务写入；失败不部分保存。沿用 mutation／限流／幂等、逐字段编写记录、家谱修订号及缓存失效。复制快照和完整备份保留新增资料及重点选择，复制后名称沿用复制流程。无新增集合、索引或批量迁移；无图片附件、文章库、公开发布、PDF版式与后台示例编辑扩展。

各页面都有加载、无权访问、家谱不可用及可重试错误状态；归档家谱继续经原管理恢复流程，不通过新资料页绕开访问限制。异步加载与保存结果校验页面、账户及家谱仍有效。

## 5. 视觉、验收与交接

- 沿用松绿、米白、细边框与现有系统字体；正文16px起、长文约1.8行高，标题22–26px。功能热区至少44px，长辈模式至少60px，字号跟随全局设置。
- 手机单列、正文左右16px左右；宽屏正文限宽720px。保留胶囊与底部安全区，阅读状态不显示固定操作栏，编辑状态底部固定取消／保存按钮并为表单留足空间。超长名称、连续字辈、空值保留字段标签并显示“未填写”，换行可完整阅读。
- 可交互预览使用虚构资料，提供家庭入口、阅读、编辑、管理和邀请折叠；可切换查看身份、未补资料和大字号。保存只更新预览内存，邀请、权限、记录和跳转仅示意，不连接实际家谱。
- 实现验收覆盖：三角色权限、旧资料、部分填写、长文完整显示、无目录、固定底栏与末尾可达、整页草稿、未保存退出、超长与非法类型、清空重点、保存失败／重复点击／权限失效、旧客户端保留字段、编写记录、缓存、复制及备份。
- 实现后统一运行 `bash scripts/check.sh`，完成原生编译与包体检查；再以独立 staging 虚构数据验收和回读。真机覆盖320px窄屏、大字号、长辈模式及宽屏。
