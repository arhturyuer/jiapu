# 人物视角称谓：覆盖与本地验收

## 已实现行为

- 默认称谓统一；外公的姐妹称“姑姥”，外公的外甥称“表舅”。尚未提供地域或家庭自定义设置。
- 完整有效关系图上计算，折叠只影响显示。直接关系优先，其次血亲、姻亲、其他已录入连接，同类选择较近关系；同距离确定专名优先于关系说明，最后按编码稳定排序。
- 主称谓和其他成立称谓保留实际人物 ID、关系 ID 路径；同一称谓经双亲成立时合并证据。信息不足的可能称谓不作为多重关系展示。
- 不把父母的配偶、配偶的子女、共同子女的另一位家长自动当作另一种已确认关系；不自动认定继父母。
- 日期按合法日期区间比较；同年不同月可判断先后，同年仅年份、同月部分日期或相同日期不猜长幼。
- 关系连通性没有 8 步上限。静态词表支持的路径查专名，更远的直系提供代数说明，其余提供真实关系说明；无连接显示“暂未建立关系”。
- 专名搜索按词表前缀剪枝，最多每成员 64 条路径候选、每视角 100,000 个搜索状态；同视角发生截断时，成员卡提示其他路径尚未完整展开，不宣称已穷举全部关系。
- 页面自有缓存对视角、人物性别／出生日期／删除状态、关系内容变化失效；折叠、缩放、选中和横竖排切换复用。姓名在打开成员卡时从最新资料读取。
- 人物视角横排节点为 168×196 rpx、竖排为 112×212 rpx，同步连线与布局；全谱节点尺寸不变。完整称谓、多重关系和路径在可滚动成员卡查看。概览缩放沿用原有文字隐藏策略。

## 接口

- 保持 calculateKinships(persons, relations, viewpointId) 的“成员 ID → 字符串”接口。
- calculateKinshipDetails 返回主称谓 label、category、named、code、distance、description、paths、reason、alternatives、multiple、truncated。self／unconnected 没有关系路径。
- paths 保留 personIds 和 relationIds；category 为 self、direct、blood、affinal、related 或 unconnected。blood 表示仅沿已录入亲子关系先向上再向下的路径，不通过共同子女推断父母之间的血缘。
- createKinshipCache 提供页面缓存，memberKinshipCard 只为被打开的成员整理可展示路径。布局返回 kinshipDetails，但页面不把整份详情随节点发送给视图层。
- 没有云函数 API、数据库或权限变更。

仅本地构造数据验收；没有访问 staging 或生产数据，也没有执行部署。

```sh
node --test --test-concurrency=1 tests/*.test.js
```

- 称谓测试包含上述 60 组案例，以及日期合法性、输入乱序、双亲证据合并、多重关系、反向视角、删除、断开连接、搜索截断和缓存失效。
- 页面测试分别执行真实家谱与官方示例的页面处理逻辑，验证折叠后称谓一致、切换视角无旧内容、只给成员卡传入路径、横竖排尺寸和连线一致。
- 保留原有 500 人纯布局小于 1 秒测试；另起进程验证包含词表冷启动的 500 人首次称谓计算小于 1 秒。
- 使用本地静态页面加载当前 WXSS，核对四字竖排姓名、长称谓省略、多重关系提示和成员卡滚动空间；它属于样式核对，不能代替微信开发者工具或真机验收。
