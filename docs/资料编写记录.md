# 资料编写记录

本说明是人物及家谱署名、编写详情与接口的现行规范。交付状态见[本轮交接](./releases/资料编写记录-staging交接-2026-10-23.md)，部署遵循[开发部署说明](./有谱开发部署说明.md)。2026-10-24 按用户当前服务端独立交付授权完成两函数及三项审计索引生产部署和回读；小程序上传、审核和发布由人工完成，官方预览未通过且未重试。实际证据及兼容边界见[生产交接](./releases/资料编写记录-生产交接-2026-10-24.md)。

## 入口和权限

家庭页顶部资料卡底部显示整份家谱的编写者；人物详情在直接关系之后、操作按钮之前显示该人物及直接相关关系的编写者。两处入口共用样式，内嵌入口与卡片底部合计 32rpx 留白、至少 44px 点击区域，独立卡片保留自身内边距，详见[设计规范](./有谱设计风格规范.md#5-布局与空间)。整行点击进入“资料编写记录”，默认全部，可按编写者筛选。按身份去重、最近贡献倒序，名单前三位之后显示“等 N 人”；同名不同人不合并。没有可靠记录显示“暂无编写记录”，读取失败提供记录页重试入口。

当前有效的管理员、共同补全成员、只读成员均可免费查看完整编写记录。公开示例不提供本入口；跨家谱、退出成员及未登录拒绝。原“家谱变更历史”仍保留原免费最近 20 条和会员规则。

## 更新与缓存

署名摘要及记录列表均通过 App 的 `getContributionSummary`／`getContributionList` 接入原页面的 `loadCached`。统一使用一小时业务内存缓存，按账号、环境、家谱、人物、编写者及游标隔离；并发读取合并，过期重新读取，数据不写入本地持久化存储。

人物页普通打开复用缓存，下拉时连同署名一起强制刷新。家庭页署名沿用原看板的刷新参数：看板明确强刷时署名同步强刷，缓存路径复用缓存。记录页普通打开／筛选／分页复用对应查询缓存，下拉和错误重试同时强刷摘要及首屏列表。同一范围已有署名时，后台刷新保留文字，不反复闪现“正在读取”；切换账号、环境或资料范围会重新进入加载状态。

人物、家谱资料及关系／排序实际保存、审核通过，沿原写入更新和失效入口使该家谱的署名及所有筛选分页缓存失效；待审核或拒绝保留编写缓存。退出家谱和权限失效沿原清理机制失效，退出账号／切换环境沿原缓存域清空。原版本与会话检查阻止写入前或旧账号的迟到响应回写。

## 写入与归属

复用 `audit_logs` 及现有保存事务、幂等机制，一次生效保存最多一条编写记录。记录实际变化的字段，保存相同内容不新增贡献；原审计和家谱版本协议保持兼容。覆盖创建家谱及初始人物关系、名称介绍、人物新增／编辑／删除、关系新增／移除、子女排行和夫妻顺序。删除人物同时记录被移除的直接关系，所有受影响人物均可查询。邀请、权限、会员和复制家谱操作不作为资料编写；副本不复制原历史，也不把复制者署名为原资料作者。

普通成员申请仅在通过时记录，归提交人，并附审核人及通过时间；前值使用通过事务内实际资料，待审核和拒绝不产生贡献。注销后署名匿名化，编写详情仍随家谱保留，到期清谱沿用现有审计删除流程。

人物包括姓名、性别、生卒时间、在世状态、籍贯、简介和头像；生卒日期合并为显示字段，保留公历／农历、年／月／日精度和闰月。空值显示“不详”。头像仅记录新增、更换、移除，不保存历史媒体地址。关系和排序记录可读前后值与所有直接受影响人物 ID。业务详情仅保存于业务数据库，运行日志不记录姓名、简介或媒体地址。

旧记录不回填、不猜测前后值，只展示可确认的摘要，标注“早期记录未保存修改详情”。旧通过记录需关联同谱且已通过的申请确认提交人。旧创建记录不能推断初始人物归属；关系记录只在原关系可确认时关联两端。

## 接口与数据

用户端均使用 `type` 和原有 `success/data`、`success/code/message` 协议：

| 接口 | 输入 | 输出 |
|---|---|---|
| `contribution.summary` | 必填 `familyId`；可选 `personId` | `authors: [{key,name}]`、`count`，按最新贡献排序 |
| `contribution.list` | 同上；可选 `authorKey`、`cursor` | `items`、`hasMore`、`nextCursor`；每页最多 30 条 |

详情项白名单为 `_id`、`authorKey`、`authorName`、`reviewerName`、`reviewedAt`、`summary`、`changes`、`legacy`、`createdAt`。`changes` 含 `objectName`、`field`、`label`、`before`、`after`，头像额外提供 `description`。对外编写者 key 是家谱范围内的摘要值，不返回内部用户 ID、openid、请求凭据或原始记录。

新审计增加 `contributionVersion: 1` 和可空的 `contribution`。空值表示该次保存没有实际编写变化，不能退化为旧摘要。结构包含 `authorId/authorName`、`reviewerId/reviewerName`、`personIds`、`changes`。不新增集合，不改变 schema v14；新字段均可选，旧客户端仍使用原接口。备份 CSV 增加编写详情列，仅导出姓名、审核姓名与字段变化。

查询依照 `createdAt desc, _id desc`，游标含二者，避免相同时间翻页遗漏。按百条扫描并投影旧／新记录，无静默截断；编写者摘要扫描完整家谱历史，不受原会员限制。新增 `audit_logs` 的 `family_created_id_desc`、`contribution_author_id`、`contribution_reviewer_id` 索引，后二者服务账号注销批处理。注销分别匿名化操作者、编写者、审核人，并沿用维护任务范围护栏。参数错误使用 `INVALID_CONTRIBUTION_QUERY`／`INVALID_CONTRIBUTION_CURSOR`；身份与归属错误沿用既有错误码。接口只读，不新增写入幂等要求。

## 验证与维护

执行 `bash scripts/check.sh`，覆盖真实路由事务、权限、审核、日期、排序、旧记录、相同时间分页、注销、入口状态及迟到响应隔离。源码 `assets/contributions/` 保存入口工具及未改变算法的称谓／排行模块，记录页直接维护原生页面源码；运行 `node scripts/package-contributions.mjs` 生成压缩发布副本，再运行 `node scripts/package-pdf-layout.mjs` 同步共享依赖。统一检查验证生成副本一致及主包体积，不放宽原门槛。

仅独立 staging 使用虚构数据验证，部署 `youpuUserApi`、`youpuJobs` 并应用审计索引，回读源码及索引。无需运营后台或安全规则变更。小程序上传、体验版设置、提审和发布由人工负责；开发版 develop 路由 staging，入口为家庭页资料卡及人物详情页。
