# 有谱小程序适老化调研与实施计划

> 文档状态：规划草案；调研日期：2026-10-11。用户已授权实施，并后续确认唯一入口在我的帮助与反馈，关闭长辈模式保留字号、恢复普通交互；实际源码及验收边界见[适老化说明](./适老化说明.md)。当前产品规则见[当前能力与边界](./当前能力与边界.md)，界面约定见[设计规范](./有谱设计风格规范.md)，设备布局见[大屏说明](./大屏适配说明.md)。本草案不能作为修改广告、会员、权限或生产部署的授权依据。

## 1. 结论与目标

建议在现有原生 JS/WXML/WXSS 小程序内改造，保留家谱特色和现有接口：所有用户可调字号，普通模式保留原有操作方式；长辈可主动启用大按钮、简化操作的模式。模式属于个人阅读偏好，不改变家谱内容、他人显示、角色和会员权益。

交付目标是让长辈能够独立完成“打开家人分享 → 找到一位家人 → 查看资料与关系 → 添加或修改资料 → 知道保存或申请结果”。不能只放大首页，也不能用画布放大代替表单、弹框和协议文字适配。

可达到的程度分三层：

| 层次 | 能力与范围 | 可行性与边界 |
|---|---|---|
| 全体基础改善 | 统一字号机制和必要的大字防裁切适配；覆盖全部原有页面和共用组件 | 普通模式保留原操作方式；专属大按钮、简化操作及持续结果按长辈开关生效 |
| 长辈模式 | 简化家谱工具、突出找家人和看资料、较大姓名、关系文字解释、渐进表单、稳定的帮助与退出入口 | 推荐首个完整交付范围；已确定保留现有广告 |
| 深度无障碍 | 列表和详情提供等价任务入口，兼容读屏，弹层和更新后的焦点可用 | 分设备逐项验收；复杂画布不能仅补标签就视为完成 |

自动语音建谱、方言识别、全程语音导航和正式适老化认证不纳入首版。语音输入可先验证系统键盘的可用性；如以后增加应用内录音、识别或朗读，再独立评估隐私、费用、名字识别及错误纠正，不直接接入第三方服务。

## 2. 调研依据及适用边界

只采用政府、W3C 和微信/腾讯官方开源项目作为技术依据；以下是参考目标，不代表本小程序已达标或已获认证。

| 依据 | 对本项目的启示 |
|---|---|
| [工信部 2021 年通知及 APP 适老化规范附件](https://www.miit.gov.cn/jgsj/xgj/gzdt/art/2021/art_eddf498ded1b44829644bf20d28c9f6f.html) | 适老界面主要文字至少 18dp/pt，主要文字最大可调至少 30dp/pt；主要组件热区 60×60dp/pt，其他页面主要组件 44×44dp/pt；适老界面禁止广告内容及插件。作为设计参考，不能推断小程序认证适用范围 |
| [WCAG 2.2 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | 普通文字至少 4.5:1；大字例外有独立定义，不把中文 18px 自动当成可降到 3:1的大字 |
| [WCAG 2.2 文字放大](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) | 将 200% 文字放大仍能获取信息和操作作为工程目标 |
| [WCAG 2.2 最小热区](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[增强热区](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html) | AA 最小热区是 24 CSS px 并有例外；44 CSS px 对应增强条目。项目主动选择更大热区，不能把 44px 误称为 AA 的统一门槛 |
| [微信小程序适老化转换工具](https://github.com/wechat-miniprogram/miniprogram-elder-transform) | `page-meta root-font-size="system"` 与 rem 可参与字体适配；工具明确仍需手动适配和测试 |
| [腾讯 WeUI 小程序示例](https://github.com/Tencent/weui-wxss/blob/master/src/example/index.wxml) | 已有 system 根字号及 aria-role、aria-label、aria-hidden 的官方实践，可作为试验依据 |

单位不能混用：工信部的 dp/pt、WCAG 的 CSS px 与小程序 rpx 不是同一单位。375px 逻辑宽度下 36rpx 约为 18px，320px 宽时只有 15.36px；不能把“36rpx”作为全设备达标证明。项目尺寸以实测逻辑 px 建立工程门槛，正式标准评测的单位对应关系另行确认。

微信开发者文档的 API/无障碍页面本轮浏览返回访问错误，因此不锁定未经复核的最低基础库版本，不承诺所有 ARIA 属性、原生控件或系统字体档位均支持。实施前通过官方文档及真机核实 `wx.getAppBaseInfo` 的字号信息、`page-meta`、可用读屏属性与事件；当前官方开源代码只能证明存在实现路径。

## 4. 推荐产品方案

### 4.1 所有人获得基础改善

- 默认跟随微信字号，同时提供应用内字号选择和实时预览；关键文字普通基准约 16px，说明按重要程度分层，条款、价格、错误、权限结果不降为难读小字。
- 普通模式保留原按钮尺寸；长辈模式主操作优先 60px，按钮有间隔，不能靠相互覆盖的透明热区凑尺寸。
- 普通模式保留原图标操作、错误提示和保存后自动返回；长辈模式补可见文字、错误定位与持续结果。
- 大字时允许换行、单列和纵向滚动；保存底栏可两行或主次分布，不将并排按钮硬塞进小屏。
- 选择、错误、权限及人物状态同时用文字表达；关系说明不只依赖颜色和线条。

### 4.2 长辈模式入口与偏好

- 唯一入口为“我的 → 帮助与反馈 → 长辈模式与字号”，显示开启状态，加载/失败时也可进入；首页、家庭、图谱更多及隐私页不提供设置入口，不要求先成为管理员。
- 用户主动开启；不推断年龄、不收集年龄、不因为大字自动认定长辈。字号与简化模式分别可调。
- 首期本机保存并立即应用全部页面，返回和重新进入保持；新增隐私中心说明与重置行为。按设备保留的字号不会强行同步到另一台手机。
- “跟随微信”与“手动字号”明确优先级；手动选择覆盖跟随值，恢复跟随后重新读取。长辈模式为字号提供可见默认建议，不能与微信倍率重复相乘。
- 保留原有家谱显示偏好；模式的推荐横排和智能收起不写回或覆盖用户原设置。若需暂时覆盖，退出必须恢复原值。

### 4.3 家谱和关系浏览

- 将常用入口收敛为“找家人、放大/缩小、看清姓名、更多”，提供大按钮。图片、PDF、横屏、显示设置等放入可发现的更多面板。
- 长辈模式姓名初始目标 20–22px，提供“看清姓名”恢复取景；整图概览仍允许缩小，但明确回到可读大小的入口。
- 放大节点文字必须同步验证卡片尺寸、夫妻及亲子连线锚点、徽标、长姓名和多重关系；不能在固定 168×164rpx 卡片里只加字号。
- 保留单指拖动及按钮缩放，使主要任务不依赖双指、长按或再次点击小“•••”。节点选中后提供可见“查看资料”“添加亲属”入口，详情也能继续操作。
- 突出当前人物视角，以完整句子解释“从张建国看，张小明是孙子”；复杂关系沿用现有可信路径，不增加未经验证的推断。
- 成员列表和详情可完成找人、看资料、理解直接关系；必要时从详情提供父母、伴侣、子女的文字列表。读屏入口不能要求先在画布命中某个人。
- 清屏退出增加可见文字及大热区；关闭、方向切换、切字号后保持人物与逻辑中心。减少流光等非必要动效，但不能关闭加载和保存状态反馈。

### 4.4 表单、邀请与安全操作

- 表单先显示必填姓名、性别、健在/已故及必要关系，头像、籍贯等渐进补充；公农历、闰月、“只知道年份”和取消不保存的规则保持。
- 关系操作增加自然语言确认，如“将李芳添加为张建国的母亲”；保留重复姓名提示、共同父母/子女确认及普通成员审批规则。
- 长辈模式必填错误显示在字段附近并能定位，保存或审批结果持续显示；普通模式保留原提示和保存后自动返回。两种模式均保留未保存提醒、输入和重试规则。
- 邀请说明用短句明确将加入哪份家谱及获得的身份；求助保留微信客服/现有反馈入口，不新增未运营的电话服务承诺。
- 支付显示家谱、金额、期限和结果；删除、移交、归档、注销明确影响及二次确认。简化界面不取消权限、确认、审核或去重护栏。
- 关键帮助允许用户主动关闭，不自动闪退；现有自动引导的时间和频率逐项复核，不能扩大成不断打扰。

### 4.5 广告与会员的已确定方案

用户在开发计划阶段明确选择“保留现有广告”。长辈模式沿用开屏、顶部、人物弹框、会员免广告和计时规则，仅放大应用自有操作按钮、改善重排及开屏空间分配；不裁切或拉伸原生素材，不改平台配置。

不实施调研最初建议的无广告分支；不宣称为无广告认证适老版。实际实现与待验收项见[适老化说明](./适老化说明.md)。

## 5. 实现方案与技术试验

保留现有技术栈和 API。首期预计以客户端为主，不需要数据库、云函数、索引或安全规则变更；本机偏好不加入 `family.setPreference`。跨设备同步、服务端统计或语音服务如以后需要，再另列接口兼容方案。

1. 新建独立偏好工具，统一解析跟随/手动字号、模式及版本默认值；已有用户默认普通模式，缺失配置安全回退。
2. 普通界面用语义字号和尺寸变量，选择性改造 rem/计算字号及容器。先实测 `root-font-size="system"`，核对微信档位与实际 px；避免同时设置根字号及再乘 API 倍率造成二次放大。
3. 合并已有 `page-meta` 的方向、resize 和字号职责，不新增相互冲突的节点；保持 `launchAd.wrap` 与设备封装的生命周期、清理及入口恢复逻辑。
4. 图谱几何与界面字号分开。将节点度量和姓名可读比例做成受控参数，必要时同步布局；仅字号档变化时重算，拖动/缩放不重新布局。现有海报及 PDF 样式单独控制，不因本机字号意外改变导出成品。
5. 大屏生成脚本继续生成尺寸基线，新增语义变量须有明确保留/转换规则，适老覆盖与手写布局的优先级一致；600px 和 1024px 边界双侧检查。
6. 以原生按钮、字段标签及受支持 ARIA 属性补充语义，装饰线隐藏于读屏，列表次序稳定。焦点管理能力先实测，不直接套用网页 DOM 焦点 API。

不运行自动转换工具改写整库。官方工具适合验证机制，本项目的固定图谱几何、大屏生成块和已有 `page-meta` 需要人工规划。

## 6. 分阶段执行计划

估算为单人开发工作日，包含有针对性的测试和文档，不是自然日承诺；首版约 10–16 个工作日。设备借用、用户招募、产品决策及人工审核等待不计入。第一阶段结果可缩减或扩大后续估算。

| 阶段 | 估算 | 范围与产出 | 进入下一阶段的条件 |
|---|---:|---|---|
| P0：机制与样例验证 | 1–2 日 | 29 页/共用组件问题清单；我的、家谱、添加成员三页字号和重排试验；iOS/Android 根字号、日期、原生导航及读屏试验；长辈模式原型 | 字号来源及无重复倍率可证明；大屏、画布坐标方案明确；广告保留，入口及字号机制可验证 |
| P1：全体基础改善 | 2–3 日 | 全局字号/偏好与预览；全页热区、关键小字、对比、弹层、错误和反馈；再生成大屏样式 | 普通模式不退化；核心链路 200% 文字可用；29 页清单无遗漏的关键障碍 |
| P2：长辈核心流程 | 3–5 日 | 家谱/家庭/我的入口、简化工具、成员列表/详情、关系解释、创建/添加/编辑/日期、邀请；保留广告并改善自有操作区 | 两种模式贯通全流程，换页/重启/直达无错乱；保留原广告规则，两种模式可验证 |
| P3：读屏与边界补齐 | 2–3 日 | 搜索和列表、详情关系、表单、弹层/错误焦点；会员、导出、隐私、法律说明、管理危险操作及其余二级页 | iOS/Android 主要任务可用；原生及平台问题有实测证据和替代路径 |
| P4：staging 试用与交付 | 2–3 日 | 大字、小屏、大屏、500 人及权限回归；长辈任务试用与问题修复；更新现行文档和版本交接 | 必须项通过；不将本地通过当作真机或发布通过 |

实施优先级：首批落在 `tree`、`members`、`profile`、`person-list`、`member-detail`、`example`/`examples`/`example-person-detail`、`display-settings`、`create-family`、`add-member`、`edit-member`、`invite`、`notification-entry` 和日期/关系共用组件。其余会员、管理、导出、隐私、反馈、法律等页随后补齐；第一版长辈模式对外提供前，所有可到达页面都应纳入验收，不能停留在首页大字。

## 7. 验收标准

### 7.1 必须通过的工程检查

- 全部 29 页及共用组件有记录，覆盖加载、空、失败、无权限、保存中和成功；字号设置在无需家谱时可用。
- 普通主要正文约 16 逻辑 px；长辈模式主要正文约 20px、重要辅助文字至少 18px。主要文本最大可调至少 30px；所有字号档需实测，不以 rpx 声明替代结果。
- 从各模式基准测试 100%、125%、150%、200% 文字放大；长辈基准 20px 的 200% 应达到 40px，不能按普通基准 32px 顶掉。允许重排和纵向滚动，不丢内容、按钮、输入或协议入口；更大微信字号另列实测边界，不静默当作已支持。
- 普通操作热区至少 44×44 逻辑 px；长辈模式主操作优先 60px，关闭/取消至少 44px。原生控件逐项测量；画布概览缩小节点时须提供符合热区要求的等价列表操作。
- 普通文字对比至少 4.5:1，必要图形和控件状态参考 3:1；不能靠颜色区分状态。逐项检验实际背景、禁用例外和原生导航，而非整页平均值。
- 在 320/375/430px 手机逻辑宽度、横屏、键盘打开、600px 和 1024px 边界、iPad 和电脑微信下可达主要操作；日期取消、农历闰月、部分日期不退化。
- 家谱切模式/字号/方向、搜索定位及清屏往返保持所选人物和合理取景；长姓名、多祖先、多配偶、竖排、折叠完整且无新增错连线。
- 保留现有 500 人布局低于 1 秒的本地测试门槛；真机记录首屏、拖动和缩放表现。本地耗时不能证明所有真机不卡顿。
- 普通、只读、管理员的授权和申请语义一致；支付取消/待确认、保存失败重试不重复写入，危险操作确认不减少。
- 冷启动、分享及通知直达、切谱、弹框、迟到回调和模式切换保持原广告与会员规则；大字关闭操作不遮挡、不裁切原生素材。
- `bash scripts/check.sh` 通过；更新样式生成产物，保持包体预算。文档改动不新增镜像实现的无意义测试；后续新增偏好/模式时测试状态转换、失败、入口恢复和几何行为。

### 7.2 读屏与真实长辈任务

设备测试至少包含 iOS VoiceOver、Android TalkBack 或该设备等价读屏工具，并记录系统、微信版本、基础库、字号档及设备型号。分别测试找人、看资料/直接关系、填写必填字段、识别保存或审批状态、关闭弹层及求助。检查可访问名称、角色、选中/禁用状态、朗读顺序、隐藏内容和返回焦点，不能只用静态 ARIA 数量验收。

先邀请 5–8 位自愿长辈作形成性试用，覆盖熟悉微信和不熟悉微信、轻度视力下降及手部操作不稳等情况，使用 staging 虚构家谱。每人完成：

1. 从分享入口打开，开启模式并调整字号。
2. 找到指定家人，查看资料，解释与指定视角人物的关系。
3. 添加或修改一位虚构家人，知道保存完成还是等待管理员。
4. 返回可读家谱、关闭弹框、找到帮助，再退出模式。

建议内部放行目标：至少 80% 参与者不经主持人代操作完成每项核心任务，参与人数小于 10 时按人数向上取整；所有任务失败均定位原因；不得出现无法恢复的误付款、错误危险操作或资料丢失。逐项记录完成率、用时、误点、求助和主观可读性，比较改造前后的同类任务并考虑学习效应。小样本用于找问题，不能作为总体用户成功率或认证证明。招募、录屏和反馈由用户协调且取得参与者同意，不在本轮发送外部消息。

### 7.3 环境及发布

调研及本次入口调整未进行云端操作。联调/验收默认独立 staging，使用 develop 开发版和虚构数据；入口仅为我的 → 帮助与反馈 → 长辈模式与字号。trial/release 路由 production，不能拿来进行未授权的 staging 验收。

云函数若无变更无需为界面改造重复部署；如确需服务端变更，由 AI 在获授权环境部署并回读。遵循[正式发布手册](./正式发布运行手册.md)。
