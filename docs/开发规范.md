# 有谱开发规范

本规范用于当前代码及后续功能迭代。文档入口与有效性见[文档索引](./文档索引.md)，实际功能见[当前能力与边界](./当前能力与边界.md)。环境授权以根目录 [AGENTS.md](../AGENTS.md) 为准。

## 1. 目录和代码约定

| 层 | 职责与约定 |
|---|---|
| 小程序页面 | 原生 JS/WXML/WXSS/JSON；页面维护交互、加载/空/错误状态和生命周期，业务请求统一经过 `miniprogram/utils/api.js` |
| 小程序工具 | CommonJS；纯计算、显示映射、缓存与文件传输分别组织，算法不得依赖页面实例 |
| 云函数 | JavaScript/CommonJS；按现有用户、运营、任务、支付通知边界部署；入口组织路由、鉴权和公共错误/日志处理，新领域逻辑放在对应函数目录内 |
| 运营后台 | Vue 3 + TypeScript，保持 strict 检查；统一使用 `admin/src/cloudbase.ts`，按功能提取组件与纯逻辑 |
| 部署工具 | `.mjs` 使用 ESM，Shell 使用 Bash 和 `set -euo pipefail`；所有云端操作保留目标环境校验 |
| 测试 | Node 内置 test runner，使用虚构数据与依赖替身，不调用真实云端 |

- 两空格缩进、UTF-8、LF、文件末尾换行；JS/TS 使用分号、单引号（字符串包含单引号时允许双引号），模板、JSON 遵循各自语法。格式以 `.editorconfig` 和邻近代码为准，不顺带格式化整库。
- 变量/函数采用 camelCase，类和类型采用 PascalCase，静态常量采用 UPPER_SNAKE_CASE；新工具文件使用 kebab-case，Vue 组件使用 PascalCase。沿用既有页面 `index.*` 结构。
- 大文件按本次变更涉及的职责逐步提取；纯整理与业务行为变更分开审查。不为达到行数目标拆文件。
- 云函数不得直接依赖部署目录之外的相对路径；公共代码如需复用，必须先建立明确的打包方式与部署验证，不能假设仓库根目录会随函数上传。
- 依赖变更显式锁定版本并更新已有锁文件。第三方词表使用既有重建脚本、来源校验和许可证，不手工修改生成词表。

## 2. 接口、数据与兼容性

- 保留现有协议：用户端动作使用 `type`，运营端使用 `action`（兼容既有 `type`）；成功返回 `success/data`，失败返回 `success/code/message` 及现有可选 `details/requestId`。新增接口写清输入、权限、输出、失败与幂等语义。
- 身份和家谱权限由服务端校验；客户端显示控制不能代替鉴权。用户端和运营端都不得直接读写业务数据库。
- 输入使用白名单、长度和合法值校验；多记录一致性写入使用事务。重试复用幂等键，新增关键写接口同步登记既有 mutation/限流机制，不自动重试业务拒绝。
- 列表沿用对应接口的稳定游标和排序；图谱遵守现有人数与关系上限，不静默截断。字段与索引变更同步检查集合初始化、安全规则和部署步骤。
- 服务端先部署时，当前正式小程序及待审版本必须同时可用。优先增加可选字段、默认值和新接口；删字段、改语义需分阶段迁移，并证明旧客户端已不再依赖。不能以审核提交成功代替兼容验证。
- 回滚以已验证兼容的代码版本为单位；不能用恢复旧代码覆盖已提交的数据变更，不能未经验证改回旧 `familyFunctions`。

## 3. 页面、错误和隐私

- 页面具备加载、空数据、成功和可重试错误状态；异步结果检查当前页面/家谱是否仍有效，离开页面清理定时器与订阅。
- 图谱避免在每次拖动或缩放时重复计算和大规模 `setData`；写入后按已有版本/缓存规则失效，保留 500 人性能回归。
- 服务端业务错误使用稳定 code 和可展示 message；异常细节不直接返回用户。日志沿用 requestId、匿名 actorId、action、耗时和结果字段。
- 不记录密钥、访问令牌、原始 openid、姓名、简介或媒体地址；本地密钥和环境文件继续忽略，测试不读取这些文件。
- 媒体准入、人工复核和存储访问边界以[开发部署说明](./有谱开发部署说明.md#6-内容安全与媒体)为准，不能把图片复核模式误写为始终先机审后展示。

## 4. 本地检查与测试

需要 Node.js 20.19+、pnpm；首次安装后台依赖使用 `pnpm --dir admin install --frozen-lockfile`。日常检查不自动安装依赖、不联网、不调用微信 CLI。

```bash
bash scripts/check.sh
# 只构建本地产物；环境 ID 由操作者显式提供
VITE_CLOUDBASE_ENV=<独立staging环境ID> bash scripts/check.sh --build-admin
```

可用 `NODE_BIN`、`PNPM_BIN` 指定工具路径。检查包含自有 JS/MJS 语法、文档结构、全量测试、后台类型检查；构建模式通过后台 build 自带的 vue-tsc 完成类型检查。生成目录、依赖、本地环境配置不扫描。构建通过不代表云端部署或真机验收通过。

- 新业务优先验证输入输出、状态变化、权限与失败路径；修复明确错误先复现再加回归测试。静态契约用于路由/结构约束，不取代行为测试。
- 测试需要小程序环境时引入 `tests/helpers/test-environment.js`：执行真实路由代码，仅注入虚构 staging 配置。不得将测试兜底加入应用启动代码。
- 文档、格式调整不新增无意义测试；检查工具需验证失败传播、无凭据运行、参数错误和排除目录。云端预检仍使用原有脚本，不能用本地检查绕过其护栏。
- 当前小程序为单主包，包体回归保守限制源码总量小于 1,500,000 字节、图片和音频合计不超过 200,000 字节，并检查每个媒体文件。源码统计不代表微信编译包大小；仍需在开发者工具重扫代码质量并记录实际预览包字节数。称谓词表编码变更需从锁定来源重建，核对全部条目和查询，保留许可及来源指纹。

## 5. 文档与代码同步维护

所有自有 Markdown（包括新增未提交文件）登记到[文档索引](./文档索引.md)。每条记录写明用途、状态、核验日期、依据、替代入口和处理原因。历史记录、规划草案、已废弃文档顶部必须标注状态并链接现行说明。

- 产品行为变更更新当前能力及相关验收文档；界面约定变更更新设计规范；环境、函数或部署变化更新部署手册及交接模板；开发约定变化更新本规范和 AGENTS。
- 历史发布数据保持原样，追加状态说明，不把旧数据改成新结果。未实现想法单列规划，不因文档写过就视为已实现或授权实施。
- 文档与代码冲突要结合用户要求、业务规则、实现及测试判断；证据不足列待核验项，不能简单以代码或文档单方面为准。
- 文档检查只验证登记、状态、替代入口、本地 Markdown 链接和标题锚点，不验证外链可达性、云端事实或所有业务语义。当前支持行内和完整/折叠引用链接；不要使用不带定义的引用或仅标签式快捷引用来链接仓库文件。
- 每次交付写明文档更新项或无需更新的理由；发布前复核本次涉及的现行说明。无法确认且影响部署安全的事项阻止相应步骤，其他事项明确记录。

## 6. AI 与人工分工

AI 完成代码、检查、staging 服务端部署、回读与验收证据；当前请求明确授权 production 后才部署生产服务端。人工负责小程序上传、体验版设置、提交审核和发布，以及平台专属配置。

使用[发布交接模板](./releases/TEMPLATE.md)分别记录服务端与小程序状态。保留上传脚本供人工执行；AI 不运行 upload、提交审核或发布操作。不把服务端部署成功表述为小程序已上线。
