# 「有谱」开发部署说明

> 文档状态：现行规范。描述仓库部署契约，不代表线上状态已核验；核验日期和依据见[文档索引](./文档索引.md)。

## 1. 系统边界

`family.create` 的 `relatives` 接受可选布尔字段 `parentsAreSpouses`。只有严格为 `true` 且父亲、母亲均成功创建时，才在原创建事务中通过现有关系方法保存一条 `spouse` 关系，并计入 `relationCount` 和 `relationRevision`。省略、`false` 或非布尔值保持原创建行为；单亲不生成夫妻关系。权限、幂等及返回协议不变，无需修改索引、安全规则或迁移已有数据。

用户端和运营端都不直接读写数据库：

| 入口 | 服务端 | 权限边界 |
|---|---|---|
| 微信小程序 | `youpuUserApi` | 微信登录用户 + 家谱角色 |
| 运营管理端 | `youpuOpsApi` | CloudBase Auth v2 登录 + `operators` 白名单 |
| 用户触发后台任务/每日保留任务/审核回调 | `youpuJobs` | 禁止客户端调用，仅接受服务端异步派发、平台触发或带部署密钥的内部调用 |

旧 `familyFunctions` 保留为遗留代码。是否仍被调用需要在授权环境核验；不得默认作为回滚入口或直接删除。停用需独立变更安排与客户端兼容证据。

`family.getPreference`、`family.setPreference` 和 `graph.get` 的显示偏好包含 `autoCollapseEnabled` 布尔字段。服务端与客户端都把缺失字段解释为 `true`，因此无需迁移已有 `user_family_preferences`；旧客户端会忽略新增字段。关闭后客户端完整布局所有成员，手动折叠和既有图片可读上限仍独立生效。

`person.createRelated` 和 `person.update` 可接收可选的 `birthDateInfo`、`deathDateInfo`：`{calendar: 'solar'|'lunar', precision: 'year'|'month'|'day', year, month, day, isLeapMonth}`，空值清除对应日期。服务端校验并保存原始历法和精度，返回可换算时的 `birthDateRange`、`deathDateRange`（`start`／`end` 公历日期）。旧 `birthDate`、`deathDate` 继续承载公历字符串；旧客户端仅传这些字段时按公历处理，未触及日期的旧请求不清除新增信息。早于可验证换算范围的农历保留原值，不生成区间；新增字段不需要数据库迁移、索引或安全规则变更。

管理员 `person.update` 和 `change.review` 批准成员资料申请时，日期信息及区间对象使用 `db.command.set` 整字段替换。CloudBase 的普通对象更新会展开为子字段路径，无法在存量 `null` 下创建字段；不能用整人物文档覆盖来规避此问题。申请载荷、接口返回及幂等结果保留普通日期对象，不存储数据库指令。清空日期仍写空值，无需迁移存量 `null`。

成员日期 staging 验收使用 `deployment/verify-member-dates-staging.mjs`，显式设置 `DEPLOYMENT_TARGET=staging` 和受控的 `STAGING_ENV_ID`。脚本下载实际用户 API 源码，部署随机密钥及运行编号保护的临时探针，以虚构身份执行真实鉴权、日期处理、事务和审核获批逻辑；通知发送不在此探针验收范围。完成后回读日期并清理虚构记录、删除探针；失败明细及源码指纹保存在忽略的受控备份目录。它不代替微信开发版页面或真机验收。

## 2. 环境

- 仓库约定生产环境：`cloud1-d5gs5yj4l283d9c6d`；历史角色变化不能作为新请求的授权或当前线上验收证据。
- 测试环境：使用独立 CloudBase 环境；环境 ID 仅保存在被忽略的 `deployment/staging.local.env`，再由 `deployment/configure-staging.mjs` 生成本机小程序配置。不得将 production ID、密钥或真实个人数据写入 staging。
- 小程序环境开关：`miniprogram/config/env.js`，必须由构建脚本生成本机 `env.local.js`，不允许默认回退到 production。
- 管理端环境：构建时通过 `VITE_CLOUDBASE_ENV` 注入；缺失时生产构建会失败。

小程序使用微信官方 `wx.getAccountInfoSync().miniProgram.envVersion` 在运行时路由：开发版 `develop` 连接 staging，体验版 `trial` 与正式版 `release` 连接 production；未知值安全降级到 staging。上传脚本的 `staging` / `production` 参数用于验证预期运行版本，不生成不同环境的代码包。仓库支持通过显式确认使用平台 `PRIVATE` 云存储权限作为个人套餐基线，并由服务端校验对象路径和真实大小、执行内容审核、仅返回审核通过的临时链接。不要把生产密钥或真实个人数据复制到测试环境。

## 3. 运行时与依赖

四个活动云函数目标统一使用 `Nodejs20.19`，版本、超时和内存以 `deployment/cloudbaserc.example.json` 为基准：

| 云函数 | 超时 | 内存 |
|---|---:|---:|
| `youpuUserApi` | 15 秒 | 512 MB |
| `youpuOpsApi` | 20 秒 | 512 MB |
| staging：`youpuPaymentNotify`；production：`youpuPaymentNotifyV2` | 20 秒 | 512 MB |
| `youpuJobs` | 900 秒 | 512 MB |

业务请求目标仍为 5 秒内；告警阈值见正式发布运行手册。各函数 `package.json` 固定直接依赖版本，管理端使用 `pnpm-lock.yaml`；任务函数使用传递依赖锁文件和 Linux 完整包构建，其余云函数尚无传递依赖锁文件，不能将直接版本固定等同于完整依赖可复现。

## 4. 数据初始化

仅首次建环境或本次明确需要新增集合/schema 初始化时执行。staging 使用 `deploy-staging.sh bootstrap`；以下为受部署密钥保护的请求结构，实际调用必须满足目标环境授权：

```json
{
  "action": "system.bootstrap",
  "secret": "<BOOTSTRAP_SECRET>",
  "initialOperatorAuthUid": "<Auth v2 用户 UID>",
  "initialOperatorEmail": "<运营邮箱>",
  "initialOperatorName": "<显示名称>"
}
```

它会幂等创建集合、写入 schema v12，并且只在没有有效运营账号时创建第一个 `super_admin`。之后立即轮换部署密钥，不要在日志、文档或聊天记录中保存明文。

核心集合包括：`users`、`families`、`family_memberships`、`user_family_preferences`、`persons`、`relations`、`invitations`、`change_requests`、`media_assets`、`moderation_tasks`、`reports`、`account_deletion_requests`、`idempotency_records`、`rate_limits`、`export_tasks`、`operators` 和 `audit_logs`；另有会员、官方示例、反馈群和分享指标集合。`profile_sync_tasks`、`backup_manifests`、`commerce_metrics_daily` 属于旧实现遗留，不再由活动代码读写；是否清理需单独的数据变更授权。数据管理新增每日活动、聚合、范围缓存、24 小时明细快照及清理历史事实集合，以及幂等采集开始配置；部署和接口口径见[数据管理与统计口径](./数据管理与统计口径.md)。完整活动列表以 `youpuJobs/index.js` 的 `COLLECTIONS` 为准。

## 5. 索引与安全规则

1. 运行 `deployment/apply-indexes.mjs` 按 `deployment/database-indexes.json` 创建并回读索引。唯一索引和稀疏属性必须逐项确认成功，不能只创建普通索引替代。
   索引清单版本 10 保留原版本 9 为 `relations` 增加 `familyId + status + fromPersonId` 和 `familyId + status + toPersonId`，供 `person.get` 定向查询当前人物关系；相关人物按最多 50 个 ID 一组读取。API 返回结构和服务端鉴权不变，不迁移历史数据。部署到 staging 后需回读两项索引并检查人物详情耗时。
2. 数据库应用 `deployment/security/database-deny-all.json`。
3. 当平台拒绝 `CUSTOM` 规则且确认使用个人套餐基线时，使用 `ALLOW_PERSONAL_PRIVATE_STORAGE=1` 显式接受平台 `PRIVATE` 生产基线。对象创建者按平台权限可访问本人上传对象；服务端必须校验签发路径和云存储返回的真实大小，家庭成员只能通过审核通过后签发的临时链接展示。未来套餐支持时再切换到 `deployment/security/storage-private-staging.json` 的 `CUSTOM` 规则。
4. 云函数规则按 `deployment/security/function-rules.json` 回读。`function-rules-after-stabilization.json` 是旧 API 停用候选规则，只有确认旧客户端不再依赖并获得对应变更授权后才应用；日常发布不自动切换。
5. 用三个测试账号分别验证 `admin/member/viewer`，并额外验证未登录、跨家谱和非运营白名单访问全部被拒绝。

`youpuUserApi` 还需在函数 OpenAPI 权限中包含 `wxacode.getUnlimited`。家谱图片本身只在小程序本机画布生成；服务端为当前真实家谱成员签发固定 viewer 权限的长期邀请和小程序码，为已登录用户生成定位到已发布示例全谱或人物视角的示例码。示例码不创建邀请或家谱成员关系，示例下架后失效。staging 使用 `develop` 码验收，体验版与正式版分别使用 `trial`、`release`，不得把开发版二维码作为生产发布证据。

订阅消息在用户业务事务提交后由小程序直接触发的 `youpuUserApi` 调用 `subscribeMessage.send`，该函数须配置同名 OpenAPI 权限。先前由 SCF 异步派发至 `youpuJobs` 的方式在 staging 两次测试中均以 `-501001` 失败；微信云调用需要小程序发起时的票据，不能依赖普通 SCF 异步调用。微信公众平台已选定两类模板：家人加入使用“新成员加入通知”（编号 75343，`thing1` 为新成员、`time2` 为加入时间），待处理申请使用“待办事项提醒”（编号 2983，`thing1` 为事项主题、`thing4` 为事项描述）。两类模板 ID 和实际字段键填入独立 staging 的 `deployment/staging.local.env` 中 `STAGING_NOTIFY_*` 项，再生成清单并部署用户与任务函数；未完整配置时功能保持关闭。加入时间按北京时间 `HH:mm` 发送，staging 消息强制跳开发版。家谱与家庭页邀请卡在转发按钮被点击后，由用户点击弹层外遮罩关闭分享卡片，同步调用 `wx.requestSubscribeMessage`；弹层不设关闭按钮，普通页面返回或分享回调不得自动调用。该自动请求不调用小程序 toast，即使微信记住选择并跳过官方弹框；家庭页用户主动点击“提醒设置”后仍显示结果提示。真实家谱图片分享仍由用户点击引导中的“开启提醒”请求订阅，家庭页“提醒设置”也可再次订阅，普通一次性订阅每次授权通常只对应一条消息。`notifications` 集合记录事件与逐人发送结果；发送失败不得回滚加入或资料申请。部署需同步应用 `notifications.kind_status` 索引，使用测试账号核验两类消息、去重、拒绝订阅及跳转；模板 ID 和实际键值只需保存在受控环境配置与平台记录，不应把测试账号资料写入仓库。

普通微信邀请 `invite.create` 接受当前家谱有效 `admin/member/viewer` 身份；请求 `role` 仅为 `member` 或 `viewer`，且不得高于分享者当前角色。`viewer` 只能创建 `viewer` 邀请，`member` 和管理员可创建两种邀请；人物视角的 `viewPersonId` 仍须为同一家谱有效人物。角色以事务内成员记录为准，客户端选项不代替服务端校验。既有 `invite.list`、`invite.revoke` 继续由管理员操作，旧客户端创建的管理员邀请请求及邀请接受协议均保持兼容。

production 首次启用订阅提醒按[正式发布运行手册](./正式发布运行手册.md)提供六项 `PRODUCTION_NOTIFY_*` 配置并生成受控生产清单，跳转版本固定 `formal`；后续部署保留线上一致的模板配置。生产回读同时校验两端配置、派发密钥和目标环境，不能仅部署代码后假定提醒已启用。

待审核角标使用用户端只读动作 `change.pendingCount`：输入 `familyId`，服务端要求有效用户及该家谱的有效成员身份，返回 `{ count }`。管理员统计该家谱所有 `pending` 申请，member 仅统计 `createdBy` 为自己的申请，viewer 返回零；无权访问仍按既有错误协议拒绝。该接口不写数据、不需要幂等键，使用已有 `change_requests` 复合索引，不需迁移或修改安全规则。提醒分享链接携带 `familyId` 和 `review=1`，待处理页再次验证管理员角色；客户端角标与入口判断不能替代服务端 `change.review` 鉴权。

不得对整个存储 `staging/` 前缀配置 24 小时过期删除：当前上传和审核通过后的图片都保留在此路径，没有迁移到永久前缀。该前缀是对象路径，不代表云环境角色。整前缀清理会误删仍被引用的头像。已配置的云端生命周期需在获得相应环境授权后核验；不能据旧手册继续添加。上传中断且未回传 fileID 的孤儿清理仍是待完善项，需要按资源状态/引用核对后设计，不能用一刀切的过期规则代替。

索引清单是可审查的部署契约；不同 CloudBase 控制台版本不保证支持直接导入，实际结果以控制台索引状态为准。

## 6. 内容安全与媒体

- 部署基线要求 `CONTENT_MODERATION_MODE=strict`，禁止将代码中的 `off` 分支用作发布配置。图片另有数据库内的准入策略，由超级管理员配置，不能与该环境变量混淆。
- 文本在写入业务数据前同步审核；可疑文本进入 `moderation_tasks`。
- 图片先上传私有暂存目录，服务端核对路径和真实大小。默认审核模式等待机审/人工复核；图片复核模式（`review`）会先置为 `approved + active`，记录机审结果，后续可由运营标记违规并停止展示。两种模式都保留审核记录；上传时策略固定在资源上，后续切换不重新解释旧资源。
- `media.getUrls` 仅为具备访问权限的 `approved + active` 资源签发短链；PRIVATE 存储基线下对象创建者仍可能按平台权限访问本人原文件，不能承诺原文件对所有人均不可读。
- 在微信/CloudBase 控制台配置 `security.mediaCheckAsync` 回调到 `youpuJobs`，用通过、疑似、违规测试图分别验证默认审核模式状态流转和复核模式的机审记录、人工违规隐藏；具体状态以资源捕获的策略为准。
- 审核回调未验证前，不得开放正式图片上传。

## 7. 运营后台

1. 在 CloudBase Auth v2 启用内置 `email` 身份源和邮箱密码策略，关闭匿名、用户名和手机登录；管理端不提供注册入口，运营 API 仍必须校验 `operators` 白名单。
2. 由控制台创建初始账号，再通过 bootstrap 写入 `operators` 白名单。
3. 构建：`VITE_CLOUDBASE_ENV=<环境ID> pnpm --dir admin run build`。
4. 将 `admin/dist` 部署到该环境的静态托管。
5. 配置静态站点域名/CORS，仅允许受控运营域名调用。

`operator` 可以处理举报和复核；`super_admin` 额外管理运营账号、冻结与注销重试、图片准入策略。当前不要求通用工单关联和所有操作填写原因，但举报处理必须填写结论，拒绝复核和标记违规必须填写原因。受控访问记录具体运营账号并审计；运营端不能修改真实家谱人物关系，官方示例有独立管理入口。

官方示例每份最多 200 人、400 条关系，超限请求分别返回 `EXAMPLE_MAX_PERSONS`、`EXAMPLE_MAX_RELATIONS`，不截断保存。内容校验失败沿用现有 `success/code/message/requestId` 协议，并可选返回 `details.validationIssues` 数组。每项包含 `scope`、`rowIndex`、`sheetRow`、`field`、`message` 及可选 `relatedRows`；`rowIndex` 和 `relatedRows` 为从 0 开始的数据下标，`sheetRow` 为包含表头的 Excel 行号。详细人名只返回给已鉴权运营人员，请求失败日志不记录该明细。

示例 `description` 在草稿及发布内容中最多 1000 字（包含空格和换行），保留段落格式，超限返回 `EXAMPLE_DESCRIPTION_TOO_LONG`，不截断保存；`examples.list` 和 `examples.get` 返回已发布版本的完整简介。普通家谱简介仍为 200 字。

`examples.create` 与 `examples.updateDraft` 的 `draftContent.relations` 可提交 `fromPersonName/toPersonName`，服务端先按本次提交的人物姓名唯一匹配，再执行关系、重复项和祖先循环校验，最后生成或保留内部 ID。旧的 `fromPersonId/toPersonId` 请求及已保存草稿继续兼容；姓名缺失、重复或无法匹配时返回上述结构化错误，不选取第一个同名人物。

示例创建和草稿更新可提交 `draftDisplayPreference`，包含 `nameLayout`（`horizontal` / `vertical`）及四个布尔字段 `showChildRankBadge`、`showGenderBadge`、`showGenderColors`、`autoCollapseEnabled`。字段缺失时保留已有草稿值；旧示例没有该字段时使用横排、关闭两个标识、开启性别配色和智能收起。发布将草稿值复制到 `publishedDisplayPreference` 并写入版本快照，回滚同时恢复；`examples.get` 返回 `publishedVersion` 和已发布值 `defaultDisplayPreference`。小程序按示例及发布版本保存本地显示偏好：发布新版本后忽略旧版本本地值，先采用新默认；用户重新调整后仅对当前版本生效。无效字段或类型返回 `EXAMPLE_DISPLAY_PREFERENCE_INVALID`，不改变已发布示例。

## 8. 状态与数据生命周期

- 家谱：`active / frozen / archived / deleting`；归档 30 天后异步清理，可在到期前恢复。
- 邀请：`active / revoked / expired / exhausted`；新建 `purpose=direct` 普通邀请的 `expiresAt`、`maxUses` 均为 `null`，即长期有效且不限加入人数，旧客户端提交的 `expiresInDays`、`maxUses` 不再改变新邀请规则。历史邀请仍按已保存的到期时间和次数上限判定，不迁移或恢复已失效链接；`purpose=poster` 的图片邀请固定 viewer、无到期时间和使用次数上限。两种邀请均可由管理员撤销，家谱归档/删除或创建者注销后停止使用。历史邀请缺少 `purpose` 时继续按普通邀请解释。
- 媒体：`pending / approved / rejected / review`；准入行为取决于上传时的图片策略，详见第 6 节。
- 注销：`pending / cancelled / processing / completed / failed`；7 天冷静期，之后匿名化账户，保留由家庭共同维护的人物资料。
- 个人导出和家庭完整备份：用户申请后，`youpuUserApi` 以 SCF `Event` 模式异步派发指定任务 ID，`youpuJobs` 事务抢占并执行；不再由定时器轮询待办队列。家庭备份页面仅在前台按 4～30 秒退避查询状态。
- 资料同步：用户保存昵称或头像时由 `youpuUserApi` 同步更新其活动成员记录，不再写入定时同步队列。
- 支付：以平台消息推送为主，用户打开待确认订单时可显式触发 `payment.reconcileNow` 查单；后台不再周期扫描全部待确认订单。
- 每日 03:00 仅运行 `youpu-retention-maintenance`，处理注销、归档家庭、临时记录、超时/过期导出等保留期事务。
- 举报：`open / processing / resolved / rejected`。

关键业务写操作沿用已登记的请求幂等键机制；新增写接口必须逐项核验覆盖。家谱、关系、审核、邀请、角色、归档和注销状态变更使用数据库事务。列表使用游标分页，图谱接口硬限制为 500 人并明确报错，不做静默截断。

### staging 测试身份重置

`account.resetTest` 为独立 staging 专用接口，输入 `envVersion=develop`、`expectedUserId` 和现有幂等请求键，返回 `{ reset, userId, archivedFamilies }`。身份从微信上下文取得，只能重置调用者；冻结账户或已执行中的注销任务拒绝。入口先验证服务端 `STAGING_ACCOUNT_RESET_ENABLED=1`、`STAGING_ACCOUNT_RESET_ENV` 与实际云环境完全一致且不是 production，再执行限流和写入，每小时最多 20 次。`configure-staging.mjs` 自动注入这两项变量，生产清单不注入。

事务注销旧用户、关闭有效成员身份、撤销旧用户有效邀请、取消冷静期任务；唯一管理员家谱沿用 30 天归档保留期，其他管理员家谱继续保留。随后创建新的用户 ID，并在既有 `system_config` 写入 `staging_identity_<匿名摘要>` 指针。staging 请求在独立异步上下文解析该指针，用户 ID、成员身份文档键与偏好文档键均按身份隔离；重新加入曾经加入的家谱也不继承旧视角与设置；未配置独立 staging 身份目标的环境保留原确定性身份算法，不读指针；只关闭重置开关时仍解析已有身份指针。重试幂等记录先于用户状态检查，避免超时后再次注销新身份；客户端附带的 `testActorId` 拦截旧身份迟到写请求。事务遵守[CloudBase 官方事务限制](https://docs.cloudbase.net/database/transaction)，只使用单文档操作，发现关联记录用普通查询并在事务逐项复核，数量超过 40 个有效成员身份、100 个有效邀请或预估 95 次事务操作时整体拒绝，不截断；staging mutation 与重置均先写入用户文档取得同一身份锁，避免发现关联记录时漏掉旧身份的并发写入。

无新增集合、索引、安全规则或 schema 迁移。旧用户资料清空、移除 openid；历史家谱、偏好、审核、订单及媒体等测试记录保留在旧用户 ID 下，新身份不会继承。这是测试身份重置，不替代正式注销的隐私清理任务。启用后回滚必须保留身份指针解析，否则已重置用户会重新指向已注销旧 ID；只隐藏客户端按钮或关闭新重置请求时仍应保留现有指针解析。验收使用可丢弃 staging 账号，不能直接注销日常账号作为冒烟测试。

## 复制真实家谱

`family.copy.create` 输入 `familyId/name/requestId`，返回任务状态；`family.copy.status` 输入 `taskId` 或 `familyId`（本人该来源的最近任务），返回 `task`，无记录时为 `null`。沿用 `success/data` 和 `success/code/message` 协议，客户端经 `api.call` 的 `idempotencyKey` 转为 `requestId`。仅有效账户、有效真实家谱的 admin/member/viewer 可发起；任务仅发起者可查。完成后必须仍有目标家谱访问权才返回家谱资料和缺失头像人物明细。

任务创建登记 mutation；每日限额单独在 mutation 事务内执行，避免全局请求限流把网络重试算成新发起。每用户北京时间自然日最多 3 次、同时一个任务，拒绝不扣额度，任务接受后失败不退额度；相同请求键不重复创建，改变内容复用键返回 `COPY_REQUEST_CHANGED`。`users.copyDay/copyCount/activeCopyTaskId` 为可选字段。创建次数超过限制、已有任务分别返回 `COPY_DAILY_LIMIT/COPY_IN_PROGRESS`；非法名称返回 `COPY_NAME_INVALID`。

schema v11 新增 `family_copy_tasks`（私有状态、发起者/来源/目标 ID、执行令牌、进度及检查点）和 `family_copy_chunks`（每块最多 20 个人物或关系的私有快照）；两集合禁止客户端直读写。新增索引为任务的发起者/来源/创建时间、状态/ID、清理标记/ID和快照的任务/ID。`families.contentRevision` 缺失视为 0，由用户 API 的实际资料、人物、关系变更及审核通过在同一业务事务内递增；邀请、待审核提交和审核拒绝不递增。服务端先部署，旧客户端请求协议不变，无历史迁移。

后台读取快照前后核对版本，冲突最多重读 3 次；完整关系必须无悬空端点、重复边、自关联或祖先循环，最多 500 人/2000 条关系。开始及最终发布重新校验账户、原谱状态及身份，后台快照取得后的普通编辑不进入本次副本。新人物/关系 ID 全部映射，子女排行与生卒历法、精度保留；不包含协作者、邀请、待审核申请、已删除记录、历史及会员订单权益。

头像只从来源家谱 `active + approved` 的人物头像复制，服务端下载原字节并上传到同环境 `family-copies/<任务ID>/`，新媒体归复制者与目标谱。预先登记确定文件 ID，便于上传响应丢失及硬超时清理；不开放客户端该路径的写入权限。不可用/失败头像以默认头像完成并列出人物。目标记录写入尚不存在的家谱 ID，全部核验后以事务创建家谱、唯一管理员身份和完成任务，不出现半成品；创建日期与首次创建转化均在成功时写入。副本不依赖原谱文件。

`task.family-copy` 接入现有密钥鉴权和异步派发。每次任务最多使用 12 分钟处理预算，检查点继续异步派发；独占租约 16 分钟长于部署的 900 秒最大执行时间，所有任务写事务核验令牌。状态读取可重新派发 pending 或租约过期任务，重复派发不重复写入。已有每日保留任务重派未完成任务；超过 24 小时仍未完成则标记失败并清理。失败文件和快照清理未成功保留标记重试，成功快照及时清理。`youpuJobs` 新增固定版本 SCF SDK 与函数本地派发模块，需要与 user API 同样具备调用同环境 jobs 的运行角色权限及 `JOB_FUNCTION_NAMESPACE`。两份派发模块由测试核对一致。

staging 先部署 jobs、bootstrap 初始化集合及当前 schema v12、应用新增索引和权限，再部署 user API；使用现有护栏与回读脚本。后台无页面变更，无需重建运营后台。可运行 `DEPLOYMENT_TARGET=staging STAGING_ENV_ID=<独立staging环境ID> node deployment/verify-family-copy-staging.mjs` 进行虚构数据后台验收：短批次准备、异步派发、后台真实文件下载验证及分批清理，临时函数只在 staging 使用并要求密钥。夹具不替代真实微信登录和文字审核验收。执行及真机状态见 [复制家谱交接](./releases/复制家谱-未发布-2026-10-06.md)。
